# 0022 — 以观察为依据的人员认可

状态：已采纳（2026-11-15，用户确认后实施）

## 背景

人员认可推荐启动审核，知识版本认可确认一项共识，两者不能复用票数或额度。旧版允许直接把人物状态改为审核中，需要收束网页与 MCP 的所有入口。

正式方案链接本次仍无法读取；本决策依据用户在本轮明确确认的人员认可方案。未据此推断正式方案中未确认的知识认可、关闭和到期规则。

## 决定

认可对象为人物，每份认可固定引用一条观察及内容版本。有效个人账号绑定开启中的正式社员档案才具资格，管理员与普通成员相同，服务账号无独立投票权。额度按社员档案、北京时间自然月计量，每月两份，不随账号改绑重置。

每人物每轮每社员最多一份；三份有效认可与一个待领取审核任务同一事务提交。跨月不使旧认可到期。撤回留下记录、不退额度，本轮不可再次提交；已经触发的任务保留，负责人收到提醒。观察编辑不改写历史依据，删除依据不参与尚未触发的计数。

任务结束或档案关闭后本轮结束，旧票不自动进入新轮。审核和入社分别通过既有任务交付推进。旧的正在进行的人事任务及既有社员继续有效；不提供“管理员跳过认可”的新建入口。

数据库归属为人事主库；知识独立库不变。网页和 MCP 使用同一服务、事务校验及幂等收据。Agent 写入需用户对具体人员认可的明确授权。

## 后果

状态直改、直接引荐及伪造规则任务不能绕过门槛。迁移保存旧任务的历史身份，不伪造三份认可。迁移后旧代码仍可读取数据，但数据库禁止其恢复旧的直接审核入口；回退不删除认可或恢复该绕过路径。历史社员漏档使用独立的「补录历史社员」命令，任一已登录人事账号均可使用，网页与 MCP 同权。须按 QQ 核对，并在同一事务中写入原入社依据和操作者。
