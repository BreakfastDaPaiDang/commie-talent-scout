# 组织共用知识库，按工作选择默认阅读范围

**进度**　已实现主站与独立 MCP 按多个已认可标签读取生效全文。下述自动选择范围的规则供组会讨论。启用前，人事会话仍默认通读全部生效知识。

**收录和使用要分别回答两个问题。** 一篇稿件校对方法经三人认可，说明组织愿意把它作为共同参考。主持人事审核时是否需要通读这篇文章，取决于手头的工作。两种判断可以共用一份文章、一套认可和一段修订历史。

## 建议怎样使用

将少数已有知识标签指定为默认阅读的依据。例如指定「全组织通用」「人事」「文案」。「共识」「方法」「题目」继续帮助搜索，各组都可能写「方法」。给文档挂工作方向也是一次编辑，随该文档版本一起认可。专写某项工作时通常只需选一个方向。需要多方使用的文章可以选多个。

选择「通用」时问一句：即使在做完全不同的工作，遗漏这条知识也会影响判断吗？Agent 可以在写稿时建议适用方向，由成员在认可版本时一起核对。相似度搜索适合发现补充材料，用它决定必读正文容易漏掉与用户措辞差别较大的通用约定。

| 本次工作 | 默认读全文 | 可按需找 |
| --- | --- | --- |
| 准备人事审核 | 全组织通用、人事 | 对方提到的具体专业或项目 |
| 校对一份稿件 | 全组织通用、文案 | 涉及的活动资料 |
| 人事与文案一起安排作者试稿 | 全组织通用、人事、文案，共用文章只出现一次 | 本次稿件的背景资料 |

「邀请作者试稿」可以同时标人事和文案，一次修订，两边都能读到新版本。「交付如何署名」若确实要求各组交付时遵守，可标通用。一个运动项目收录的技术史料也可搜索和引用。只有审核涉及这个项目时，才需要调它的全文。读到案例或问题范例时，保留其原有用途。

## 谁维护什么

- 作者在正常写作时选适用标签。文档和标签均生效后，文章自动进入对应范围。已有版本的标签或正文正在修订时，沿用已入库版本。标签改名沿用原标识，各组无需逐篇调整。
- 建议知识库只维护一份有版本的阅读配置，其中记录通用标签及各方向对应的稳定标签标识。配置中的方向可以直接使用标签标识。组会确认第一版，日后按现有三人认可流程修订。新增常规文章走原有入库流程；只有增设工作方向或修改阅读规则时才改配置。生效配置应由系统按字段读取，普通文章中的文字不能更改其他 Agent 的阅读范围。
- 人事审核等已有明确用途的入口可传入约定方向；通用入口根据用户明确交代的工作选择，跨组任务可以合并多个方向。同一个成员转做文案时随任务切换。用户仍可要求跨组检索或通读有效全库；方向筛选沿用调用账号原有的可见权限。
- 已入库且未标方向的文章保留在全库。首次启用前用本地预览列出各方向实际会读的标题、尚无方向的文章，从当前有效全库反查每条不可遗漏的人事原则是否命中，连同贴错方向或方向标签尚待认可的情形一起核对。关键原则全部命中后再切换。日常只在入库时或发现漏读时补标签。未配置的工作继续通读生效全库；显式选取的配置若失效，接口提示范围不可用。日常审核可向使用者说明后回到完整生效库；用户明确限制阅读范围时，先核对范围再继续。已经配置但恰无专项文章时，照常读通用部分。

主持一次审核与修订一条组织规则需要不同的阅读广度。主持人可以按人事范围开始，发现专业问题再扩读；成员提出跨组共识、检查全组织规则冲突时，Agent 应显式切回有效全库，引用可能受影响的原条文。仅阅读过某个方向时，关于遗漏或冲突的结论也只覆盖这个方向。

## 接口与切换

当前 `knowledge_documents` 支持 `scope: "main"` 配合 `any_tag_ids`（标签标识数组）。服务在分页前取并集，返回命中文档的生效全文与标签。省略过滤可通读全库。未知或待认可的标识会返回范围不可用，避免把少读了一部分误报成已读完。读取同一范围时逐页核对 `branch.head_id` 和 `tag_revision`。

未来启用自动选择时，由服务统一将工作方向展开为通用及专项标签，两个 MCP 入口共享同一实现，返回本次方向和命中依据。会话的读取凭证应包含阅读配置版本、所选方向、生效文档及标签快照。任务换方向也要刷新；先后读过的相同文档版本可以复用。全文搜索仍用于查范围外的材料。这样每个 Agent 只需说明在做什么，不需要各自保存标签表、文章清单或另一份知识库。

**组会可以直接试的一步**　各选一篇“所有组开工都要读的”、一篇“只有人事审核才要读的”和一篇“文案、人事都用得上的”，看成员能否说清各自的用途。确认这三种结果，再决定启用哪些默认阅读方向。
