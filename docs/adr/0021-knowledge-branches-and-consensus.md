# 文档分支与共识选择

2026-11-13，用户确认以分支组织知识库修改，三名及以上正式成员同意取得合入资格；多个达标候选并存，通过会议或议题选择主分支内容。

采用独立库内的不可变文档版本、提交关系、分支快照及合并请求。无需为普通使用者建立真实 Git 账号，也不把私有业务内容放进 GitHub。分支控制版本范围，分类组织该版本的文档，合并请求承载修改审议，议题承载问题讨论。

此决定替代 ADR 0019 的七天期限和先到三票自动淘汰其他修订规则，也替代 ADR 0020 把 issue 采纳直接等同于知识共识的安排。独立数据库、主站身份核验、历史保存和资源唯一权威边界不变。

同意绑定不可变提交。合并必须再核对分支头、主分支变化及当前达标候选集合；多个达标候选需要可追溯选择结论。选择不会删除其他候选。批注记录原版本与引用范围，无法可靠重定位时保留旧引用，不猜测归属。

2026-11-13 后续修订：用户要求补齐“草稿 → 公开候审 → main／主要”，并将分类从文档创建中拆开。单篇提交建立只含该文档改动的公开审核快照，其历史不链接私人草稿分支，私人批注不随之公开；源草稿与其他篇目保留。新单篇审核的第三名正式成员点赞与无冲突合入在同一事务内完成。有并行替代方案时先保留候审，多个达标候选仍需会议或议题选择。旧的整分支合并请求保留显式合入流程，避免改变已经发起的审核行为。

分类保留稳定身份，名称与解释可独立维护，独立创建的空分类保留。解释沿用不可变文本版本保存；批注定位到具体解释版本，议题保存原批注与引用快照。直接公开私人批注会暴露未提交材料，因此仅可从已经可公开的来源发起成员议题。两项取舍保留原身份、独立数据库与历史边界。
