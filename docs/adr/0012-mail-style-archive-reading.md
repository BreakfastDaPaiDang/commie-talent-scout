# 网页按本次打开确认整张档案，MCP 保留逐事件阅读

日期：2026-09-10。状态：采纳。关联：Issue #36。替代 ADR 0006 的网页确认触发规则；事件存储、权限过滤和 MCP 内容票据继续沿用。

用户要求采用邮件式阅读：成功打开一张人物或组织档案，就清除这次打开时已有的可见未读，无需逐条滚动、展开或反复点击下一处未读。它表示成员打开过该档案，不声称每段内容都进入过视野。

网页详情响应签发短期档案阅读凭据。一个 D1 原子 batch 固定成员、连接、档案、最大事件序号及当时可见的未读事件集合；仅保存事件引用，不复制正文。成功展示详情、页面位于前台且没有弹窗遮挡后，网页提交该凭据。后台、读取失败、失效的迟到响应及手机端隐藏详情不确认。

确认在同一事务内复核成员、连接有效性、管理员身份（如适用）、凭据期限和档案删除状态，再按当前来源权限写入 `event_read_marks` 并记录凭据已处理。每张凭据只执行一次，丢失响应后的重试不扩大首次成功确认的范围；确认时不可见的来源不被旧请求在恢复后补读。后来新增的事件不在打开范围内，列表或编辑后的自动重读也不扩大本次范围。确认响应提供成员、事件上界及上界内仍未读的例外，供队列同步。

关闭档案仍能阅读。整档删除或恢复会撤销旧档案凭据及其临时事件引用，回收详情不签发普通阅读凭据；恢复后须重新打开。凭据 24 小时失效，定时清理连带删除临时引用；长期个人阅读标记不变。不增加业务事件，不修改档案版本或活动时间。

网页未读队列保留固定上界及已阅位置；下一处未读查询当前仍未读的其他档案，跨越未加载分页和人物／组织，不再在同一档案逐事件停留。卡片、范围计数与导航从同一个个人事件结果刷新。原型模拟同样的打开行为，共用界面布局不变。

MCP 的档案元数据和列表查询不签发档案打开凭据，也不确认阅读。Agent 仍只在实际收到所需完整内容后使用 `confirm_reading` 逐事件确认；两种入口共享个人已读结果。旧版服务可以继续读取新增迁移之前的结构；回退代码不删除新表或已有阅读标记。
