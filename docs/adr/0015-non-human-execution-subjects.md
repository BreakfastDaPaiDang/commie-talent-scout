# 非人类执行主体与早纪（人事版）

2026-10-12 讨论确认：后台自动化与未来常驻人事 Agent 不应借用某个真实社员的 MCP 凭据，也不应简单伪装成一个拥有全部管理员权限的机器社员。系统需要支持非人类执行主体，并区分固定系统规则与 Agent 自主执行。

1.0.0 先建立任务来源所需的主体契约和显示身份，不实现完整的常驻 Agent 管理平台。人事 Agent 的非人类主体名称确定为 **早纪（人事版）**，头像使用组织提供的 Q 版头像。

2026-10-12 最新澄清：用户所说“自己人”指 **猎头管理的账号列表**，不是社员档案。早纪作为独立服务账号出现在可用账号/已冻结列表，使用专属头像；不为它创建人员档案。此前关于社员档案绑定的解释撤销。开发 Agent 测试账号与早纪不是同一主体；旧账号无用途后再冻结，不重写原操作归属。

## 方向

系统可以拥有一个长期服务主体，未来常驻 Agent 可以使用该服务主体接入；但每次执行仍要记录执行方式：

- `system`：后端固定规则、定时处理或事务联动直接执行；
- `agent`：Agent 根据档案、观察、当前需求和任务上下文自主执行；
- `member`：真实社员通过网页或 MCP 执行。

服务主体作为组织内部账号出现在猎头管理，角色标识为“服务账号”。账号的存在不自动授予网页登录、领取任务或接收个人消息的能力。它也不自动拥有完整管理员能力。系统规则和 Agent 只获得明确列出的能力范围，所有写入继续经过现有权限、版本、事务、历史和重试保护。1.0.0 的周期任务在没有具体人工操作者时可把早纪（人事版）记为任务发起人。

## 审计要求

未来每次非人类操作至少应能追溯到：

- 服务主体；
- 执行方式（`system` 或 `agent`）；
- 固定规则编号、Agent 会话或调用上下文；
- 触发来源，例如定时、状态变化、人工调用或 Agent 判断；
- 产生的任务、档案变化、消息和历史。

未来 Agent 可以自主读取、分析、创建和维护任务；责任边界由服务主体、执行方式、能力范围和调用上下文表达，不要求额外绑定一个社员授权人。涉及状态切换、任务完成或档案写入时，仍必须走对应业务操作，不能绕过领域校验。由成员执行状态变化触发的自动任务，其业务发起人绑定触发该变化的操作者，不因后台规则使用早纪而改写。

## 任务来源

未来任务不应把所有来源压缩进 `manual` / `rule` 一个字段。应分别记录创建主体和触发方式，例如：

- 创建主体：`member`、`system`、`agent`；
- 触发方式：手动、定时、状态变化、Agent 判断等。

Agent 创建的任务与人工、系统规则任务共用同一任务生命周期和看板。规则性 Agent 任务需要业务义务键防止周期或状态触发重复；自由任务的去重策略留待后续设计。

## 1.0.0 边界

- 1.0.0 建立早纪（人事版）作为非人类主体的稳定标识、名称和头像展示，并让任务发起人可以引用成员或早纪；
- 1.0.0 不实现常驻 Agent 管理界面、Agent 自主任务去重或通用 Agent 工作流；
- 1.0.0 不创建机器管理员成员作为后台自动化的替身，也不借用真实成员的 MCP 凭据；
- 本 ADR 不决定未来总人员系统的账号注册方式。


## #83 实现

- `members.identity_kind` 明确区分 human/service，复用稳定 ID 和现有作者外键；`service_subjects` 持久化服务键及默认头像。早纪 ID 为 `00000000-0000-4000-8000-000000000083`，服务键/账号 `zaoji-hr`。
- 服务账号可由管理员维护名称、头像、冻结状态，并查看管理历史；不提供密码重置或管理员提权。登录、事务鉴权限定 human，数据库同时禁止给服务账号写入凭据或登录密码。当前不实现 Agent 认证平台。
- 冻结早纪暂停新的接触跟进自动任务，计划提交时再次复核冻结状态；既有任务和历史保留。解冻仍不开放网页登录。
- 系统任务的 created_by、initiator_id 和新建事件 actor_id 引用早纪，source=system 标识执行方式。原有无 ID 的 system 发起人迁移时补绑定，新增纠正事件并保留原始创建历史；真人操作触发的审核/对接任务仍归实际操作者。
- 用户原图保存在 `public/art/zaoji-hr.png`，未重新生成。猎头管理和两个任务页面统一从账号头像接口读取，上传头像优先，移除上传头像恢复专属默认图。
- 服务账号不进入真人负责人选择、任务推荐和社员档案；未来真人联系自动化基于社员档案，不得把猎头账号列表当作人员名单。
- 旧开发测试号仍用于显式开发验收，不能冒充早纪。核对并替换验收依赖后才能冻结；本次自动化已不依赖它或其他真人管理员。
