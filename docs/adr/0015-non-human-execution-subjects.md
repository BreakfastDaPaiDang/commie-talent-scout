# 非人类执行主体与早纪（人事版）

2026-10-12 讨论确认：后台自动化与未来常驻人事 Agent 不应借用某个真实社员的 MCP 凭据，也不应简单伪装成一个拥有全部管理员权限的机器社员。系统需要支持非人类执行主体，并区分固定系统规则与 Agent 自主执行。

1.0.0 先建立任务来源所需的主体契约和显示身份，不实现完整的常驻 Agent 管理平台。人事 Agent 的非人类主体名称确定为 **早纪（人事版）**，头像使用组织提供的 Q 版头像。

2026-10-12 补充确认：早纪应进入社员档案，让成员能认识它、查看职责与历史；此前“不出现在社员列表”的约定撤销。服务主体与档案应稳定绑定，档案不等于登录账号。真人月度沟通等自动化必须明确适用对象，不能因服务主体进入社员列表就自动纳入。账号、档案绑定和原头像接入仍待实现，本轮不声称其已经创建。

## 方向

系统可以拥有一个长期服务主体，未来常驻 Agent 可以使用该服务主体接入；但每次执行仍要记录执行方式：

- `system`：后端固定规则、定时处理或事务联动直接执行；
- `agent`：Agent 根据档案、观察、当前需求和任务上下文自主执行；
- `member`：真实社员通过网页或 MCP 执行。

服务主体可以是组织内部的自己人，拥有社员档案并出现在社员列表，明确标识为非人类主体。档案身份与登录权限分别表达：建立档案不自动授予普通成员登录、领取任务或接收个人消息的能力。它也不自动拥有完整管理员能力。系统规则和 Agent 只获得明确列出的能力范围，所有写入继续经过现有权限、版本、事务、历史和重试保护。1.0.0 的周期任务在没有具体人工操作者时可把早纪（人事版）记为任务发起人。

## 审计要求

未来每次非人类操作至少应能追溯到：

- 服务主体；
- 执行方式（`system` 或 `agent`）；
- 固定规则编号、Agent 会话或调用上下文；
- 触发来源，例如定时、状态变化、人工调用或 Agent 判断；
- 产生的任务、档案变化、消息和历史。

未来 Agent 可以自主读取、分析、创建和维护任务；责任边界由服务主体、执行方式、能力范围和调用上下文表达，不要求额外绑定一个社员授权人。涉及状态切换、任务完成或档案写入时，仍必须走对应业务操作，不能绕过领域校验。由成员执行状态变化触发的自动任务，其业务发起人绑定触发该变化的操作者，不因后台规则使用早纪而改写。

## 任务来源

未来任务不应把所有来源压缩进 `manual` / `rule` 一个字段。应分别记录创建主体和触发方式，例如：

- 创建主体：`member`、`system`、`agent`；
- 触发方式：手动、定时、状态变化、Agent 判断等。

Agent 创建的任务与人工、系统规则任务共用同一任务生命周期和看板。规则性 Agent 任务需要业务义务键防止周期或状态触发重复；自由任务的去重策略留待后续设计。

## 1.0.0 边界

- 1.0.0 建立早纪（人事版）作为非人类主体的稳定标识、名称和头像展示，并让任务发起人可以引用成员或早纪；
- 1.0.0 不实现常驻 Agent 管理界面、Agent 自主任务去重或通用 Agent 工作流；
- 1.0.0 不创建机器管理员成员作为后台自动化的替身，也不借用真实成员的 MCP 凭据；
- 本 ADR 不决定未来总人员系统的账号注册方式。
