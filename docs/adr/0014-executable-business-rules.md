# 以可执行定义集中表达业务联动，并自动生成规则视图

2026-09-28 确认，面向 1.0.0，尚未实施。身份、档案生命周期与任务之间开始出现多项联动；若条件和结果散落在各入口，开发者与 AI 难以完整理解，另行手工维护规则表又会产生第二份事实来源。因此决定局部重构业务代码：规则的可执行定义作为联动逻辑的唯一实现来源，规则索引与流程视图从同一份定义自动生成，不单独手工维护。

规则定义明确触发动作、适用条件和产生的变化，由共享业务模块执行；网页与 MCP 使用同一业务操作。生成视图必须读取实际参与执行的定义，不能只读取与实现分离的描述文本。复杂判断允许使用有明确名称和源码入口的函数，视图标明引用，不宣称能够自动解释任意函数内部逻辑。

重构范围限定为身份与档案生命周期联动、人事任务自动创建，以及后续确认的周期任务规则。页面归属等能从身份直接推导的结果不另设同步流程。普通资料编辑、图片等既有模块无需统一改造成规则框架；不引入通用工作流平台或用户可编辑的规则引擎。

继续遵循 [ADR 0003](./0003-shared-worker-business-layer.md) 的共享业务层，复用现有权限复核、事务、历史与请求重试机制。新增自动创建任务还须按业务触发语义处理重复与并发，不能仅依赖同一请求标识的重试保护。通过业务操作的真实结果验证规则，包括重复执行、并发和失败时的一致性；生成视图不替代行为验证。

本决定确定方向与范围，不指定配置语法、库、文件结构或完整执行器设计；这些在任务规则对齐后确定。PRD 继续维护用户目标与验收要求，自动生成的是实现规则视图，不是把产品需求从代码反推出来。

实施需求见 [1.0.0 PRD](../PRD-1.0.0.md)，接手入口与 Issue 顺序见 [1.0.0 从这里开始](../releases/1.0.0/README.md)。
