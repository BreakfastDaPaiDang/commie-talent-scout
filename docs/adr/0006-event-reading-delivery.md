# 0006：按实际交付的事件确认成员阅读进度

状态：已采用。日期：2026-09-08。关联：Issue #10、PRD 6.4。

档案里同一屏可能同时有长观察、折叠的历史变化和未加载的分页内容。打开档案或推进档案级时间水位，会错误清除成员没有看到的内容；GET 成功也不能证明客户端已收到响应。

阅读标记以成员和事件为唯一键，独立于业务版本、活动排序与写入请求收据。自己产生的事件、账号创建前事件及当前不可见的派生标签事件不计入未读。搜索、摘要与未读导航列表不创建阅读标记。

实际内容响应携带短期阅读票据，绑定成员、当前凭证、事件及观察状态版本。客户端收到内容后单独确认；服务端在同一 INSERT SELECT 中复核版本、可见性、凭证和有效期。重复确认幂等，不推进未展示事件。编辑、删除与恢复产生各自独立的新事件，过期或旧状态票据不能确认后来内容。票据 24 小时失效，定时任务清理；阅读标记随内部历史长期保留。

网页观察正文起始区域在前台进入视野 500 毫秒后确认；长卡片不要求整卡可见。后台、弹窗遮挡、失败读取与屏幕外暂停，图片正文至少等待起始图片载入。折叠的变化内容展开后才确认。MCP 通过服务内 reading 指南及工具描述要求 Agent 在实际收到内容后调用 confirm_reading，不把摘要当完整阅读。服务端不能证明外部 Agent 的主观理解。

未读分页固定最大事件序号作为本次快照，网页保留已阅条目原位；下一处未读先查询当前档案剩余事件，再跨人物、组织继续。事件和观察的直达读取独立于原列表筛选。列表摘要用批量 SQL 读取标签，避免按档案逐个查询。

代价：增加一次轻量确认请求和短期票据存储，确认失败可能暂时多显示未读；这优于错误清除没有实际展示的内容。实际浏览器前后台、滚动及队列交互仍需联验，类型检查和服务测试不能替代该证据。
