# 任务跟踪

仓库：BreakfastDaPaiDang/commie-talent-scout。
需求和开发任务使用 GitHub Issues，通过 gh CLI 操作。

- 发布到任务跟踪器：创建 GitHub Issue。
- 获取任务：读取 Issue 正文、标签和评论。
- 多行正文或评论：写入临时文件，通过 --body-file 提交。
- 外部 PR 不纳入需求分诊；开发工作可以正常使用 PR。

当前线上产品需求基线维护在 [PRD · 0.1.1](../PRD-0.1.1.md)。后续发布 PRD 到任务跟踪器时，
在 Issue 中引用对应文档和版本，避免维护两份独立演进的正文。

1.0.0 尚未上线，其唯一需求正文为 [1.0.0 PRD](../PRD-1.0.0.md)，开发接手与 Issue 索引见 [1.0.0 从这里开始](../releases/1.0.0/README.md)。不要把线上 0.1.x 的状态规则当成新版规则，也不要为每个 Issue 再复制完整 PRD。

1.0.0 实施 Issues 归入 `v1.0.0` 里程碑。正文包含可演示的完整业务路径、验收复选框、真实阻塞 Issue 与对应用户故事／验收编号；`ready-for-agent` 表示要求完整，不表示依赖已完成或功能已可上线。最终业务数据迁移与上线核对必须放在最后。文档索引不维护第二份完成状态，以 GitHub 为准。

正式首版使用 `v0.1.0` 里程碑；PRD 文档修订号和原型/探针包版本不作为产品版本。创建首版实施 Issue 时关联该里程碑，正文填写可验收路径及真实阻塞 Issue；标签 `ready-for-agent` 表示需求完整，不代表阻塞依赖已完成。
