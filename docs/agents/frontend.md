# 原型到正式前端

2026-09-09 用户明确要求：直接在已确认原型上继续实现，不再重新制作一份近似界面。

## 唯一界面来源

- `app/ui/`：从已确认原型迁出的布局、图标、基础样式、输入框、时间线、成员选择器、弹窗、资料字段与状态选项。原型和正式站共用。
- `prototypes/frontend/src/`：虚构数据与内存行为适配器，继续引用共用组件作为设计预览。
- `app/client/`：正式接口、身份、权限、持久化、加载与失败处理的适配器。保留命令版本、幂等请求、图片上传和阅读回执等业务能力。
- `app/client/extensions.css`：五分钟分组、正式连接等新增能力的样式。不能在这里覆盖原型的布局、字号、断点来维持另一套页面。

基础界面变更直接在共用组件内进行。设计变更须先向用户说明，不能把原型简单称为“示意”，自行重做导航、列表、详情或表单。新服务字段和权限约束通过组件参数或明确扩展区域接入。

## 回归

历史设计基线为 `531ab51`（第四版及电脑端打磨）。`scripts/verify-design-parity.mjs` 从 Git 读取该版本，在独立无界面浏览器中同时运行历史原型、当前原型和正式构建；检查四个宽度的基础布局指标、运行错误和关键操作，并保存对照截图。比较对象不能替换成当前代码生成的“预期”，以免两边一起回退却测试通过。将来用户确认新设计后，再更新明确的基线版本。

本机需启动 `npm run dev:worker`，然后执行：

```sh
npm run check
npm run test:dom
npm run build
node scripts/verify-design-parity.mjs
node scripts/verify-ui-simplicity.mjs
node scripts/verify-workspace-ui.mjs
```

浏览器验证使用 `playwright-core` 与本机 Edge 的独立无界面进程；可用 `CTS_TEST_BROWSER=chrome` 选择已安装 Chrome。不依赖用户当前浏览器、扩展或登录状态。对照使用虚构接口；`verify-workspace-ui` 使用隔离 staging 的真实账号、数据库、上传与命令，创建的验收档案在收尾时关闭。`--remote` 仅用于已部署的隔离测试站。

截图、样式检查和功能结果分别记录，不以单个 DOM 元素存在或 CSS 文件相同替代整体对照。正式上线仍按 Issue #14 的部署验收执行。

## 2026-09-09 的简化要求（Issue #16）

用户明确要求减少维护入口和信息负担。常态档案集中为“编辑档案”；资料、状态与成员、标签、头像在内部维护。联系方式与链接采用紧凑行，备注按需展开，切换资料/状态页签保留输入，手机端保存动作固定可见。实际字段组件为 `app/ui/ArchiveFields.tsx` 与 `forms.css`，原型与正式站共用。

观察发布不提供时间编辑，服务端记录提交时间，网页始终按 `Asia/Shanghai` 显示；既有观察发生时间作为只读资料保留。草稿状态只在有内容或正在处理/失败时出现。标签保留依据入口；常态外观按后续 Issue #17 的同类同色要求执行。Agent 接入说明用途，保留策略等内部信息不占据主页面。

范围计数由服务端在分页前计算，随当前搜索、状态、绑定成员与开启/关闭筛选变化；切换范围仍保留三种范围的总数。未读是档案数量，不是事件条数，遵循个人阅读与可见性。第一页增加一次聚合查询，后续分页不重复统计。

本次允许共用字体、发布区、弹窗底部和维护入口随反馈调整；历史 `531ab51` 仍不可变，不再要求当前三份 CSS 与它逐字相同。历史几何投影只用于守住其余布局。`verify-ui-simplicity` 单独验收完整展开状态、真实字形、跨时区、总数、手机保存按钮和迟到刷新；`verify-workspace-ui` 覆盖真实保存、标签、状态、编辑与图文发布。两类验证都要通过。

## 卡片视觉层级（Issue #17）

用户明确要求常态只显示成员与标签本身，不显示“关联成员／人事负责／标签”等字段说明。成员用头像和姓名，无人时不占位。标签同类别同色、外形统一，不以星号区分重点。用户后续明确：类别是标签含义的一部分，必须完整显示“类别：名称”，不能当作冗余字段名隐藏。删除“档案数／最近更新”整行，范围计数保留，清除条件位于筛选区。

已弃用的大叉、已入伙的大勾直接盖住左侧卡片的内容，原有头像与文字淡化，明确表达该档案已经结束、阅读优先级降低。不得给勾叉预留空位或把它缩成角落徽标。档案仍可点开查看与重新开启。

左侧头像、标题、成员、摘要、页脚字号与间距属于本次授权调整。历史对照继续使用 `531ab51` 检查其余几何；`verify-visual-cards.mjs` 检查四种宽度的覆盖关系、信息淡化、标签颜色、筛选清除与提示消失。运行独立静态预览时可用 `CTS_UI_BASE` 指向它；真实接口验收仍使用 staging。

## 注意力引导与标签详情（Issue #18）

设计应帮助成员把注意力放在需要处理的新变化和判断所需的材料。卡片未读用清楚的“有更新”提示与强调时间，常规元信息居次；已完成卡片继续淡化并盖勾叉。时间至少 14px，电脑端 15px。

标签详情以完整名称为标题，通用定义作辅助说明，具体依据居主，确认时间居后。标签区的 header/h2 等选择器必须限制在自身直接子元素，不能影响内部弹窗；查看来源、完整编辑态与手机端须分别检查。望远镜空态图属于正式资源，验收须检查真实图片解码，不能只看请求状态码。

`verify-attention-ui.mjs` 覆盖新旧资源与标题栏故障的复现、完整标签、更新标记、时间、标签来源，以及桌面和手机布局。`verify-workspace-assets.mjs` 比较实际部署插图字节，防止 SPA HTML 回退被当作图片成功。

## 可恢复移除（Issue #20、#21）

档案删除入口位于编辑窗底部；关闭档案在只读提示条直接提供删除，无需先重新开启。`app/ui/ArchiveLifecycle.tsx` 统一提示及确认内容，回收列表复用 `ArchivesPage` 与共用工作台布局。管理员菜单进入已删除档案，人物/组织切换复用范围工具条；回收详情不显示编辑、发布、重新开启或观察修改操作。

猎头管理使用共用页签切换“可用账号／已冻结”，默认只列可用账号。冻结/解冻完成后按当前范围重读，并用请求序号防止旧分页响应覆盖新范围。

`verify-archive-trash.mjs` 验收桌面/手机确认窗、取消、并发版本冲突、重读、响应丢失后的原请求重试、回收图片解码与账号冻结/解冻。仍需历史原型对照、完整编辑及发布区验证。

## 头像原色（Issue #24）

成员与档案头像保留图片原色，不用灰度滤镜统一风格。顶部账号、成员标签、详情与列表均遵循此要求；已完成档案的既有淡化层级继续用透明度表达。

## 直接复制接入（Issue #25）

用户要求复制时自动创建并携带专用认证配置，不让无浏览器 Agent 再去网页取凭据。接入页由 `AgentHandoff.tsx` 供原型和正式站共用，保留一个主要复制按钮；复制后才展示另一个 Agent 和连接管理入口。实际凭据由正式适配器创建，剪贴板失败显示同一份可选择正文。验收截图不得包含该正文中的真实凭据。

## 密码输入与页面恢复（Issue #29）

登录与改密使用共享 `PasswordInput`，原型与正式站共同提供显示/隐藏密码，输入尺寸和原布局保持。认证请求禁止缓存；页面从历史恢复或重新激活时核对当前会话，忽略已经取消或过时的响应。网络错误不当作登录失效；恢复后的未登录表单清空密码，普通切回页面不清除用户输入。不得批量清空站点存储或覆盖浏览器密码管理器。

## 档案绑定材料（0.1.1，Issue #30、#31）

用户确认在动态栏右侧增加带文件夹图标和数量的“绑定材料”页签，切换下方区域，保留顶部资料、动态位置和未提交观察。手机四个页签采用 12px 间距与 13px 字号，材料页签省略装饰图标；这是明确记录的新布局差异，历史基线其他几何与排版继续对照 `531ab51`。

材料列表、名称与说明表单、额度表单和 PDF 预览均位于 `app/ui/`，原型与正式站复用。容量、上传、回收站、下载与维护在材料页内按权限出现；普通成员不显示扩容按钮。切换全部材料/回收站立即移除旧范围内容，并忽略迟到响应，不能用旧列表版本提供新范围的操作。上传队列重试优先查询原上传，响应丢失不能重复创建文件。

PDF 以按需加载的本地 PDF.js 绘制分页画布，图片使用鉴权读取后的临时 Blob；关闭预览释放资源。文件内容不作为应用 HTML 执行，其他格式下载。静态站点 `_headers` 与 Worker 的 CSP 同步维护，包含 PDF 所需的本地 Worker、Blob 与 WASM；不放开外部脚本。

验收包含 `verify-materials.mjs --remote --large` 的容量边界和实际字节、桌面/手机完整操作，以及 `verify-material-recovery.mjs --remote --backup` 的丢失响应、拖入多文件、彻底删除、Bearer 撤销和真实备份。常态页面不得加入备份保留期、协议版本或存储实现说明。

## 词库清理（Issue #32）

标签库沿用现有页面，增加“可用词库／含停用项／已删除”范围，已删除仅管理员可见；默认只列可用项，绑定选择不加载删除内容。类别和词条详情的管理员操作增加删除/恢复，复用原弹窗和共享 `TagDeletionForm`，完整确认态才说明影响。删除完成关闭详情并重读列表；切换词库范围清除旧列表，忽略迟到响应。

`verify-tag-deletion.mjs` 覆盖真实 MCP 默认过滤、桌面删除及提交响应丢失重试、手机恢复和类别删除、名称搜索、引用保留和无溢出。仍运行历史原型对照及真实完整编辑/发布验收。`verification-client.mjs` 自动跟踪本次实际新建的类别/词条，结束时删除，重名复用的业务词义不清理；清理失败须明确报错并留下对应 ID。

## 超期未更新提醒（Issue #33）

用户要求开启档案超期时置顶并报警。共用 `ArchiveRow` 增加暖色背景、左侧强调线和“需更新或关闭”提醒，可与“有更新”并存；其余卡片保留原布局。原型以 `?reminders` 预览超期虚构档案，正式站按接口返回的 `update_reminder` 展示。

优先级由服务端在当前筛选和分页内计算，超期档案按最早到期优先，其余按最近更新。续页固定首次判断时间。可见页面每分钟及回到页面时重读已加载范围，保留选择和草稿；展开编辑窗或页面隐藏时暂停。`verify-archive-reminders.mjs` 只在隔离 staging 老化本次虚构数据，覆盖真实排序、桌面/手机并存标记、发布解除和完整手机关闭流程，最后关闭并删除本次档案、冻结测试账号并撤销连接。

## 关联我（Issue #35）

用户要求把“我负责”改为“关联我”，共用 `ScopeToolbar` 只改标签文案、保持原布局。人物及组织只要当前状态关联成员包含本人就命中，不限工作或开启状态；旧状态历史绑定不计入。正式接口保留 `scope=mine` 和 `counts.mine`，两者使用同一关联条件及当前筛选；原型也按筛选后的集合计数。既有浏览器范围偏好继续有效。

## 邮件式档案阅读（Issue #36）

网页详情成功打开且处于前台后，一次确认当时已有的全部可见未读；折叠、屏幕外和未加载分页无需逐条展示。固定本次打开凭据，列表计数、编辑或内容刷新不得扩大它；关闭、切换后重新打开才取得新的范围。后台、隐藏详情、弹窗遮挡及失败读取不确认。原型在同一套共享工作台上模拟相同行为，不改变布局。

未读队列保留已阅位置，“下一处未读”从服务端查询其他仍有未读的档案，跨越人物、组织和分页。读取响应迟到时不能覆盖新的选择，旧成员的确认不能清除新成员队列。MCP 仍使用逐事件内容票据，列表和元数据读取不清空未读。

`verify-reading-ui.mjs` 覆盖真实 HTTP/MCP 元数据无副作用、整档确认、提交响应丢失重试、后来新增事件、跨档案导航、桌面和手机编辑发布；并继续运行历史原型对照、完整编辑与发布区检查。服务测试验证个人/连接边界、关闭/删除/恢复、源权限变化和事务内鉴权。

## 辅助工具页（Issue #37）

用户确认新增推荐辅助工具页。正式站 `/tools` 从账号菜单与手机工具导航进入；原型从猎头账号弹窗与手机工具导航进入，共用 `app/ui/AuxiliaryTools.tsx` 与其 CSS。页面仅展示工具介绍、GitHub Releases、工具文档和完整启动/导出教程，不连接本机 QCE。教程与下载常量由共享模块维护。

`verify-auxiliary-tools.mjs` 检查真实 staging 登录、MCP 主题发现/读取、桌面和手机入口、链接、完整教程及溢出，并对照当前原型共享页面。继续执行历史原型对照与真实编辑、发布区回归。

## 辅助工具入口与推荐扩展（Issue #38）

用户要求右上顶栏在 Agent 接入旁常驻“辅助工具”，原账号菜单与手机入口保留。正式站和原型复用 `AuxiliaryToolsNav`，按现有窄屏规则保留带名称的图标入口、手机工具菜单；当前页标记使用 `aria-current`。这是本次授权的导航增项，其他布局继续与历史基线对照。

辅助工具页沿用 QCE 卡片与教程样式，顺序增加 SingleFile 和 Sixin.cc，卡片间留白。验证必须滚动检查三项完整内容和手机底部，不只检查第一屏；桌面工具区不得与主导航重叠。

## 互联网档案馆推荐（Issue #39）

用户澄清要的是在线网页历史服务，现用 Wayback Machine 卡片替换 SingleFile，沿用同一共享卡片布局；两种入口分别为查历史和保存当前网页。`verify-auxiliary-tools.mjs` 改为检查官方存档链接、四步教程、恢复边界和公开存档说明，继续逐项检查手机完整内容。

## 辅助工具精简（Issue #40）

按用户截图删除辅助工具标题上下的介绍、各卡片补充文档/保存链接和底部提示，只保留标题、工具介绍、主入口与完整步骤；不转移红框文案到其他常态位置。清理空白及无用样式，共享组件对原型和正式站同步生效。验收同时检查三个主入口、删除项不再出现、完整手机步骤和既有编辑发布布局。

## 随机头像装饰（Issue #41）

录用 12、15、25、28、30、35 六款，共用 `AvatarOrnament` 在每次详情挂载时抽取，编辑、数据刷新与窗口变化不重抽。装饰透明 PNG 仅用在详情已有头像周围，不改变资料和操作布局；22% 不透明度仅作用于装饰。视口至少 1100px 且标题内容区至少 760px 才显示，手机不加载；实际高度约束图案不越过资料区。完整设计、生成提示词和验收见 [头像装饰](../design/avatar-ornaments.md)。

Issue #43 按用户要求每张图分别标定头像中心，头像与图案组合后响应式缩放和定位；不能统一按标题顶部定位。组合在原布局空白内移动，不覆盖标题、编辑按钮或后续页签；局部空间不足时保留普通头像。`verify-avatar-alignment.mjs` 对六款长短标题及窗口变化检验真实中心对齐，并保存截图。
