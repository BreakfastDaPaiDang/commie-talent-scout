# 原型到正式前端

2026-09-09 用户明确要求：直接在已确认原型上继续实现，不再重新制作一份近似界面。

## 唯一界面来源

- `app/ui/`：从已确认原型迁出的布局、图标、基础样式、输入框、时间线、成员选择器、弹窗。原型和正式站共用。
- `prototypes/frontend/src/`：虚构数据与内存行为适配器，继续引用共用组件作为设计预览。
- `app/client/`：正式接口、身份、权限、持久化、加载与失败处理的适配器。保留命令版本、幂等请求、图片上传和阅读回执等业务能力。
- `app/client/extensions.css`：标签、五分钟分组、正式连接等新增能力的样式。不能在这里覆盖原型的布局、字号、断点来维持另一套页面。

基础界面变更直接在共用组件内进行。设计变更须先向用户说明，不能把原型简单称为“示意”，自行重做导航、列表、详情或表单。新服务字段和权限约束通过组件参数或明确扩展区域接入。

## 回归

历史设计基线为 `531ab51`（第四版及电脑端打磨）。`scripts/verify-design-parity.mjs` 从 Git 读取该版本，在独立无界面浏览器中同时运行历史原型、当前原型和正式构建；检查四个宽度、共享样式内容、布局指标、运行错误和关键操作，并保存对照截图。比较对象不能替换成当前代码生成的“预期”，以免两边一起回退却测试通过。将来用户确认新设计后，再更新明确的基线版本。

本机需启动 `npm run dev:worker`，然后执行：

```sh
npm run check
npm run test:dom
npm run build
node scripts/verify-design-parity.mjs
node scripts/verify-workspace-ui.mjs
```

后两项使用 `playwright-core` 与本机 Edge 的独立无界面进程；可用 `CTS_TEST_BROWSER=chrome` 选择已安装 Chrome。不依赖用户当前浏览器、扩展或登录状态。对照使用虚构接口；`verify-workspace-ui` 使用隔离 staging 的真实账号、数据库、上传与命令，创建的验收档案在收尾时关闭。`--remote` 仅用于已部署的隔离测试站。

截图、样式检查和功能结果分别记录，不以单个 DOM 元素存在或 CSS 文件相同替代整体对照。正式上线仍按 Issue #14 的部署验收执行。
