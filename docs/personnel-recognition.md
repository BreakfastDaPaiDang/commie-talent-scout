# 人员认可（主站 1.1.0）

人员认可用于推荐发起人事审核。它不批准入社，不参与知识库共识投票。知识仍存于独立库；本功能的观察、认可、额度和任务均存于人事主库。

## 使用

1. 打开外部人物档案，阅读一条具体观察，点击下方“认可此人”。
2. 确认人物、所引用的观察版本及本月剩余额度，再提交。有人认可后，可在人物详情展开人数查看认可人及依据。全部撤回后仍可查阅历史。
3. 三名不同正式社员认可后，系统自动创建一项待领取的人事审核任务。审核任务负责人交付“审核通过”后创建入社对接任务；对接负责人交付“对接完成”后转为正式社员。

当前有效个人账号必须绑定开启中的正式社员档案才能认可；管理员遵循相同条件，服务账号无独立认可权。每名社员每北京时间自然月两份，身份按社员档案 ID 计算；账号改绑不产生新额度。每人物每轮每社员至多一次，不能跨不同观察重复认可。

跨月恢复可新增额度，原认可不因此失效。撤回不退还额度，本轮不能再次认可。触发审核后撤回会记录任务动态并提醒已领取的负责人，任务继续保留。观察修改不改变旧认可引用的内容版本；已删除的观察不参与未触发轮次的计数，历史界面不泄露其正文。

审核任务完成、取消，或档案关闭、删除后本轮结束。旧认可不自动进入下一轮。若审核以“不再继续”等非通过结论结束，档案状态保留；明确退回接触等外部状态后，才可开始下一轮。不存在自动续票或认可的七天有效期；七天仅为既有任务默认期限。

## MCP

- `get_usage_guide(topic: personnel_recognition)`：资格、额度、授权和恢复指南。
- `get_personnel_recognition(archive_id)`：当前轮次、认可及剩余额度。
- `recognize_person(archive_id, round_number, observation_id, content_version, request_id)`：明确授权后提交。
- `withdraw_personnel_recognition(id, request_id)`：明确授权后撤回本人认可。

每个会话首次开展人事业务时，读取当前账号默认范围内的全部生效知识。提交人员认可需要对此人及其具体观察的明确授权。分页、快照刷新和审核协作分别见 [生效知识流程](mcp/agent-guide.md#knowledge--生效知识与修订提案)和 [人事审核指南](mcp/agent-guide.md#personnel_review--会前会中会后的人事审核)。

写入结果不明时，先用 `get_request_result` 核对原 `request_id`，重试保持原 ID 和参数。不得更换账号或反复创建请求规避额度。`refer_archive`、`confirm_membership` 和直接修改受保护状态不再是新的审核/入社入口；旧幂等回执仍可读取。

## 工程边界

`PersonnelRecognition` 是网页与 MCP 共用服务。`command` 同一批事务包括即时身份校验、档案版本校验、认可、额度占位、第三份认可的任务与历史以及请求回执。数据库唯一约束限制每月两个槽位、每轮每社员一份和每人物一个活跃轮次。并发冲突全部回滚，刷新核对后重试。

历史社员与上线前已发起审核不补造认可。测试使用显式历史样本，生产服务没有测试开关或管理员豁免。

决策依据见 [ADR 0022](adr/0022-personnel-recognition.md)。正式飞书方案本轮仍不可读取，本版不宣称核验了该文档最新正文；未确认的知识关闭、到期等规则不据讨论擅自扩大。
