# MCP 的 Agent 使用体验设计

2026-09-08 · v0.1.0 产品设计基线，正式能力尚待实现。当前明确的重点是将聊天等原始材料压缩为观察记录和有依据的标签；其他需求的优先级通过实际使用数据判断，不先展开大量假设任务。

## 1. 核心价值：减少成员整理材料的负担

用户可以直接给一段聊天记录，让 Agent 识别其中值得沉淀的信息，结合已有档案补观察记录、增减标签，必要时创建标签。用户不需要事先把材料拆成字段，也不需要逐个点名工具。

压缩有两个层次：观察记录保留事件、时间、来源、具体事实及必要背景；标签提取可复用的特征，帮助快速认识对象。标签有损，必须能回到依据；观察也不应只是机械复制整段聊天或写成失去细节的一句评价。

## 2. 默认的材料整理路线

1. **辨认对象与上下文**：区分聊天参与者、转述对象和当前成员，查询已有档案及相关记录，避免同名关联错误或重复记入同一事件。多对象材料分别归属，不把所有话算到一个人身上。
2. **提取新增信息**：压缩寒暄和重复表述，保留会影响认识的事实、具体例子、时间条件、分歧和不确定内容。区分本人自述、他人转述和成员判断。
3. **补充观察记录**：围绕同一事件或主题组织，不强制一段聊天只存一条，也不逐句拆成许多条。已存在相同材料时只补新增部分；改写旧观察仍遵守作者权限。
4. **对照已有标签与词库**：看定义及旧依据，主动判断新增绑定、补充依据、移除已不适用绑定，或创建有描述的新标签。优先复用，但确实出现新的有用特征时可以创建，不要求用户先说出准确词名。
5. **处理冲突和时效**：新材料没有提到旧标签，不表示应移除；明确的情况变化可更新，含义不清则保留冲突并简短询问。新情况不能抹掉旧观察所记载的历史事实。
6. **交付压缩结果**：简短说明补了哪些观察、标签如何变化及原因，附查看入口；没有值得改的内容就说明无新增，不为体现工作量硬贴标签。

用户要求“把这段聊天整理进档案”“补观察和标签”时，以上观察与标签维护属于整体任务，无须逐项再次授权。只给材料且意图不清时，Agent 主动提出具体整理方案，而不是等待用户学会系统操作；用户明确只要分析、草稿或单条观察时，尊重其范围。状态、责任分配、关闭与修改公共标签词义仍依相应业务意图处理。

## 3. 一个应当自然发生的例子

虚构材料：“我现在主要做访谈剪辑，上周交付了两条，链接在这里……以前那个账号已经交接给别人了。下个月备考，暂时只能周末参与。”

Agent 应识别这次材料能补充的近期工作和时间安排；若在整理档案的任务内，读取词库定义，复用合适的剪辑标签并绑定依据，检查原账号运营标签是否仍适用。交接一个账号不等于失去账号运营技能，需要区分技能与当前持有的资源。词库缺少必要的新特征时可以创建有描述的标签。

“下个月备考”和“只能周末参与”带时间范围，应在观察中保留，不推导成长期不可靠。聊天中已经给了作品链接就主动存入；没有给时，可以说明补链接的用途，不能凭作品数量推定专业等级。

最终回复应让成员看得出压缩取舍，例如：“补充了近期访谈剪辑经历和备考期间的参与时间；新增剪辑标签的作品依据；移除了已交接账号的资源绑定，保留原运营技能及历史记录。”这里的每一项均须有实际材料和已完成操作支持。

## 4. MCP 怎样帮助 Agent 完成这件事

服务入口先解释材料整理的价值，并给出这条短路线。相关工具和返回内容让 Agent 容易取得已有记录、标签定义、绑定依据和实际变化，不要求它从一个巨大手册里自行拼出流程。

首次提示词负责连接、询问临时/持久配置与核验，复制时已自动创建并携带专用认证配置，无浏览器 Agent 可直接接入；业务指导从 MCP 按需取得。已有材料就继续处理，只要求连接时提示可以直接提交材料。服务内容可以重新获取，不代表模型永远记得，关键步骤应在相关工具处也能发现。

先优化观察与标签共同维护的体验，不据此提前锁死成一个万能工具，也不预设大量会前查询、推荐和工作提醒流程。查询是整理的重要支撑能力，其独立需求大小留待实际数据判断。

## 5. 用真实请求决定下一轮优先级

首版留存 MCP 请求及执行结果，并尽可能关联一次用户任务；设计见 [外部 Agent 请求留存](./mcp-request-data.md)。分别观察用户想做什么、Agent 如何拆解、服务完成了什么。

关注实际材料整理是否经常伴随标签创建、旧标签调整、重复提交、对象歧义或局部失败。不能把调用次数等同需求次数，也不能把 Agent 最终一句“完成”当作质量证据。

初期人工审阅有代表性的任务及其观察/标签结果，检查是否漏掉重要事实、是否保留时间和归属、标签是否有信息量、删改是否有依据、用户是否需要返工。随后结合任务占比、失败点和可观察的修改继续优化。尚未传给服务的聊天内容、追问和用户反应标为不可见，不能从请求日志猜测。

通过实施切片 S5/S11 交付观察与标签共同维护，S2/S13 交付请求采集与任务审阅；见 [任务拆解](./implementation-issues.md)。技术承载见 [MCP 对接设计](./mcp-design.md)，服务规则见 [Agent 使用指南](./mcp/agent-guide.md)。
