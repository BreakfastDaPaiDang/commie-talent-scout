## 1. 问题与目标

早餐社需要一个内部协作网页，沉淀值得关注的人物与组织的信息、观察记录和接触进度。人物档案中的多数对象，是未来可能加入组织的人。

系统应让成员快速了解：对象是谁、当前进度如何、谁正在负责、最近发生了什么、此前记录了什么。多人持续维护同一份档案，避免信息分散和重复接触。

标签帮助时间有限的成员快速理解与检索能力、资源、协作方式及当前可用性；观察记录继续保留过程与依据。标签可以更新、移除和追溯，不将一次判断固化为永久属性。

产品暂定正式名称为“康米巨星猎头系统”。“插眼”是团队日常表达，产品中的主要数据概念采用“档案”“观察记录”“实体历史线”。

## 2. 需求确认程度

- **已确认**：用户明确提出，或在对齐中明确认可的规则。
- **开发默认值**：依照用户授权确定的产品或交互设计，作为首版实施依据，可以根据实际使用反馈调整。
- **技术待验证**：由开发者研究、设计和实测的事项，尚未完成验证；只有发现会改变核心范围、权限、成本或访问要求的取舍时，才重新与用户对齐。

本版本保留的“建议”措辞均表示可调整的开发默认值，不表示等待用户逐项批准。

对齐约定：仅向用户讨论 P0/P1 事项。P0 指阻止核心闭环成立或影响基本访问权限的问题；P1 指显著影响日常协作、内容处理、首版范围或接入可用性的问题。其余可逆细节由开发者采用合理默认值并记录，不逐项要求用户确认。已确认规则优先于默认值。

已确认的核心范围包括：人物和组织档案、各自的业务状态、多负责人、图文观察记录、实体历史线、关闭与重新开启、成员协作权限、记录修改留史、管理员账号管理、账号密码登录、MCP、复制 Agent 配置提示词、公开代码仓库与数据分离、优先 Cloudflare serverless 和 GitHub 更新自动部署、所有页面的视觉品质。

文档修订 1.5 已确认新增：人物与组织独立标签库、可创建类别、“类别：名称”格式、同类同色、必填且可修改的简短描述、优先复用、可见绑定统计与修改影响，以及标签定义与绑定依据分离。初始示例由开发者精简、优化并补充组织词库。

文档修订 1.6 已确认新增：MCP 以聊天等材料压缩为观察和标签为主要使用路径，Agent 主动识别相关维护动作；业务指导由服务提供，首次提示词询问临时/持久配置；留存实际请求和结果，用数据决定后续优化。请求正文 30 天、元数据 180 天及管理员审阅入口为可逆实施默认值，详见专题方案。

未读更新是用户期望功能，首版纳入简单未读列表与逐条跳转。如果实施中发现会显著影响核心交付，再说明具体取舍，不预先删减。

## 3. 用户与权限

系统只有管理员和普通成员两类用户。无自助注册。

| 操作 | 普通成员 | 管理员 |
| --- | --- | --- |
| 查看全部人物和组织档案 | 可以 | 可以 |
| 查看已删除记录的正文、历史版本和图片 | 仅原始作者自己的记录 | 任意记录 |
| 创建档案 | 可以 | 可以 |
| 修改开启中档案的基础资料、状态、负责人 | 可以 | 可以 |
| 维护开启档案的标签、依据与重点展示 | 可以 | 可以 |
| 创建标签/类别、更名及澄清描述 | 可以，查看影响并留史 | 可以，同样留史 |
| 合并重复标签、停用/恢复标签或类别 | 不可以 | 可以，查看影响并留史 |
| 给开启中的档案添加观察记录 | 可以 | 可以 |
| 修改开启中档案里自己提交的观察记录 | 可以，保留修改历史 | 可以，保留修改历史 |
| 修改开启中档案里他人提交的观察记录 | 不可以 | 可以，保留修改历史 |
| 删除开启中档案的观察记录 | 仅自己的记录，可恢复删除 | 任意记录，可恢复删除 |
| 恢复开启中档案的已删除观察记录 | 仅自己的记录 | 任意记录 |
| 关闭和重新开启档案 | 可以 | 可以 |
| 修改关闭档案内的内容 | 不可以，必须先重新开启 | 不可以，必须先重新开启 |
| 创建、冻结账号、授予管理员权限 | 不可以 | 可以，通过管理后台 |

观察记录采用可恢复删除：作者只能删除和恢复自己的记录，管理员可以删除和恢复任意记录。作者归属不因管理员编辑或删除而改变。此权限不包含永久清除记录或删除整个档案。

账号管理采用以下开发默认值：

- 账号冻结立即阻止登录及后续网页、MCP 请求，并使现有会话和个人 MCP 凭证失效；已有内容与作者归属保留。
- 管理员可以解冻账号、将管理员降为普通成员、重置密码。解冻后须重新登录并重新生成已失效的 MCP 凭证；降权立即影响后续操作权限。
- 成员可修改自己的密码。管理员创建账号或重置密码后提供临时密码，首次使用需更换；不引入邮件找回流程。
- 系统始终保留至少一名未冻结的管理员，拒绝会破坏该条件的冻结或降权操作。
- 首位管理员通过一次性初始化方式建立，具体机制在技术设计中落实，初始凭证不进入仓库。
- 账号管理动作保留操作者和时间，供管理员追溯；第一版不提供永久删除账号。

## 4. 档案与业务状态

### 4.1 共同结构

人物与组织是两种实体，分别提供入口，共用档案、观察记录、历史线、协作权限和生命周期规则。

共同信息：稳定标识、实体类型、显示名称、业务状态、开启或关闭状态、当前状态绑定成员、标签及绑定依据、创建人、创建时间、最近内容更新时间、观察记录、实体历史线。

人物以昵称、组织以名称作为必填识别字段；联系方式允许暂时未知。开发默认值：两类档案均支持可多条填写的联系方式（类型、值、备注）和资料链接；不设置别名和简介；创建时要求昵称或名称及有效业务状态，默认“视奸观察”；选择工作状态时还必须明确负责成员。

名称不强制唯一；创建前可检索并提示相似名称，避免同名不同对象无法建档。第一版不提供自动身份归并或档案合并。

### 4.2 人物状态

| 状态 | 当前成员绑定 | 开关规则 |
| --- | --- | --- |
| 视奸观察 | 可选关联成员，可多人 | 开启 |
| 个人接触 | 可选关联成员，可多人 | 开启 |
| 引荐中（待人事组接触） | 人事负责成员，至少一人，可多人 | 开启 |
| 人事审核 | 人事负责成员，至少一人，可多人 | 开启 |
| 已加入待对接 | 人事负责成员，至少一人，可多人 | 开启 |
| 已入伙 | 保留既有负责人历史 | 自动关闭 |
| 已弃用 | 保留既有负责人历史 | 自动关闭 |

### 4.3 组织状态

| 状态 | 当前成员绑定 | 开关规则 |
| --- | --- | --- |
| 视奸观察 | 可选关联成员，可多人 | 开启 |
| 个人接触 | 可选关联成员，可多人、可变更 | 开启 |
| 组织交流 | 工作负责成员，至少一人，可多人 | 开启 |
| 已弃用 | 保留既有负责人历史 | 自动关闭 |

**已确认：业务状态没有先后顺序。** 开启中的档案可以自由切换到该实体类型的任一合法业务状态，不要求经过其他状态或按某种顺序操作；切换到关闭类状态时自动关闭。系统记录状态变化，不建立流程顺序或前置状态限制。关闭后的修改仍受关闭锁定规则约束。

业务状态与绑定成员分别展示和编辑。人物的“引荐中（待人事组接触）”“人事审核”“已加入待对接”属于人事工作状态，组织的“组织交流”属于组织工作状态；这些状态必须绑定至少一名负责成员。其他状态可选择关联成员作记录，不强制。关闭状态保留关联与历史，仍遵守关闭后只读规则。

状态切换后只展示新状态的绑定成员，不把旧状态负责人继续放在当前工作区。历史保留旧关联；不在资料编辑中平铺所有状态的成员。成员选择采用可搜索的下拉多选与已选标签，适应十几名以上成员。只能新分配未冻结成员，既有冻结关联显示冻结标记。工作状态保存/重新开启时，状态与成员一起校验并原子提交，不能出现保存成功后仍缺负责人的中间状态。不得默认把调用者指定为负责人。

人物工作区称“人事负责”，组织工作区称“工作负责”，其他状态称“关联成员”；不使用“接触负责人”。工作标记描述业务责任，不新增管理员权限或账号角色。

### 4.4 关闭与重新开启

**已确认的业务含义：关闭就是停止观察，包括不再观察或对象失联；想继续观察，必须重新开启。**

- 不允许出现“仍在持续观察，但档案暂时关闭”的业务状态。
- 关闭后，基础资料、业务状态、负责人、标签绑定/依据/重点、观察记录和图片内容都不能修改，也不能新增、删除或恢复观察记录。
- 关闭档案仍可查看，历史内容保留。
- 重新开启是关闭状态下允许的生命周期操作；普通成员和管理员均可执行。
- 进入人物“已入伙／已弃用”、组织“已弃用”时自动关闭。
- 每次关闭和重新开启均生成明确的历史事件，包含操作人和时间。
- 业务状态变化同时触发关闭时，两件事都须清楚呈现，不遗漏“已关闭”的历史信息。

**已确认的关闭表达**：“已弃用”统一涵盖失联、不再在乎或其他不再关注的情况，不新增“已失联”状态，也不设置独立的关闭原因字段。需要详细说明时，成员在关闭前补充一条普通观察记录；说明不是关闭的必填条件。

关闭档案的当前展示突出“已入伙／已弃用”和“已关闭”，此前的业务状态保留在历史中。重新开启时选择一个有效的开启类业务状态；选择与开启一并完成。默认值采用关闭前最后一个开启类状态，没有该状态时采用“视奸观察”；成员可自行更换。此默认值是可逆的交互选择，不表达状态顺序。

### 4.5 标签系统

标签定义、绑定和依据分别维护，人物与组织分库，同类可多选。手工绑定已有标签保持轻量，Agent 从材料整理标签必须保留它实际读取的来源或用户明确指令；不按猜测自动补齐标签或移除未被新材料提及的旧标签。

公共标签名称、类别与描述可以修改，修改前必须展示绑定数量、档案列表及前后差异。定义澄清作用于开启档案，历史和关闭档案保留当时词义；含义明显改变时新建标签并选择有依据的开启档案迁移。合并和停用由管理员维护，不永久删除历史。具体权限是本轮开发默认值。

来源于已删除观察的绑定沿用来源读取限制，不能在标签、筛选、计数或 MCP 中泄露受限内容；独立且可见依据分别处理。完整规则、初始数值与验收以 [标签系统](./tag-system.md)为准，示例见 [人物 34 项 / 组织 31 项词库](./tag-catalog.md)。

## 5. 观察记录与实体历史线

### 5.1 观察记录

- 每个档案可以绑定多条观察记录，支持文字和图片，兼容短记事与较长文章。
- 显示提交用户、创建时间和最后修改时间。开发默认值：允许另填观察发生时间用于补录，未填写时按提交时间理解；补录时间不改变档案最近内容活动排序。
- 普通成员只能修改自己提交的观察记录，管理员可以修改全部记录。
- 每次编辑保留历史版本及修改人、修改时间；不覆盖成无法追溯的唯一版本。
- 记录采用可恢复删除：从普通列表中隐藏内容，保留记录、历史版本及关联图片，能够恢复。
- 作者只能删除和恢复自己提交的记录；管理员可以删除和恢复任意记录。权限依据原始作者判断，而不是删除人或最后修改人。
- 删除和恢复均写入实体历史线，记录操作人和时间；恢复保留原始记录标识、作者、创建时间与历史版本，不创建一条新记录。
- 档案关闭期间，即使作者或管理员也不能编辑、删除或恢复观察记录；必须先重新开启。

建议：图片修改同样进入版本历史，历史版本能够呈现当时的图文内容。图片数量、大小和保留策略在技术设计阶段确定。

开发默认值：图文编辑支持直接粘贴或选择多张图片，正文与图片至少有一项；无强制文章标题。已删除记录从普通列表隐藏，可保留“已删除”视图。只有原始作者与管理员能查看该记录的正文、历史版本和图片；其他普通成员最多看到不含具体内容的删除事件。该限制覆盖详情、搜索、摘要、未读、历史、附件地址和 MCP 响应，由服务端执行。作者权限按记录原作者判断，即使由管理员删除，原作者仍能查看与恢复。恢复后重新按普通记录可见范围展示；删除仍不是永久清除，也不能撤回他人此前已保存的副本。

### 5.2 实体历史线

历史线不仅是观察记录列表，还自动包含业务状态变化、已关闭、已开启及发生时间。建议同时记录档案创建、基础资料变更、负责人调整、记录编辑等事件，并显示操作人。

对需要追溯的字段变更，建议展示变更前后值。用户不能直接编辑系统生成的历史事件。

**观察记录必须是历史线的视觉重点，不能被操作事件淹没。**

建议交互：

- 观察记录采用更大的内容卡片，直接呈现正文摘要和图片缩略图。
- 系统事件采用紧凑行，不给每次操作相同的视觉重量。
- 提供“全部动态”和“仅观察记录”切换。
- 全部动态中，同档案、同成员的连续操作按总跨度不超过五分钟自动分组；观察正文继续显示，附带操作收为一条可展开摘要。未读队列采用相同展示分组，原始事件、历史与阅读回执不合并，未展开明细不因分组而自动已读。
- 默认按最新在前排列；长正文按需展开，图片可以放大查看。
- 记录编辑事件链接到对应记录和版本差异，避免把同一篇长文重复堆进时间线。

## 6. 页面与主要交互

### 6.1 登录

简单账号密码表单，无注册入口。登录错误、账号被冻结、会话失效等状态给出清楚反馈。

### 6.2 人物与组织列表

已确认：按档案最近内容变动排序，最近有变动的在前；观察记录变化同样影响排序。人物卡片下方罗列观察记录供查看，组织页面采用类似体验。

建议：

- 提供人物／组织切换，以及名称、联系方式、观察正文搜索，状态、负责人、开启／关闭筛选。搜索命中旧观察时显示对应摘要，点击定位该条内容。
- 默认提供“全部／我负责／有未读”范围；“我负责”只包含当前工作状态明确绑定本人的档案。高级筛选按需展开。
- 第三版交互默认值：按成员和页面记住搜索筛选，按成员和档案保留阅读位置与未发布观察草稿，跨档案查看后可继续撰写。原型只在当前内存会话保存，刷新清空；正式持久草稿另行实现并明确保存状态。
- 卡片展示名称、状态、负责人、最近更新时间和最近几条观察记录。
- 更多记录在档案详情内连续查看，避免首页加载全部长文与图片。
- 新建、编辑、删除和恢复记录，修改资料、变更状态或负责人、关闭／开启都会更新内容活动时间；无实际内容变化的重复保存不产生新动态。
- 单纯查看、自动更新阅读进度不影响档案排序。
- 默认展示开启中的档案，提供明确的已关闭和全部档案筛选。

### 6.3 档案详情与记录编辑

建议桌面端以宽侧栏呈现详情，上方为基础资料和状态操作，下方为实体历史线，直接在其中添加或编辑观察记录。

长内容可展开到更大的阅读空间，并为档案和记录提供独立链接。移动端采用全屏详情，以适应小屏幕。无需为了写一句观察笔记跳转到独立文章创作页。

关闭档案明确显示只读状态和重新开启入口。修改入口的界面限制与服务端权限检查保持一致。

### 6.4 未读更新

用户希望逐条查看上次没看过的状态更新和观察记录，并直接跳转到相应内容。

第一版提供未读列表、定位原记录／事件与下一条未读。阅读进度自动更新，不设置“标为已读”“全部已读”或逐项勾选操作。已读状态按用户独立保存。

第三版交互默认值：本次进入未读页的条目读完后原位显示“已阅”，避免列表突然跳动；“下一处未读”优先继续当前档案，再跳其他档案的具体更新。跨人物和组织时进入统一未读页。全部读完后显示完成状态。

开发默认值：

- 打开详情并实际展示对应记录/事件时自动确认已读；长列表只确认已展示的内容，不把尚未加载或尚未看到的内容一并清除。首页摘要或未读列表出现不算阅读正文。
- 页面在后台、内容未加载、权限拒绝或读取失败时不推进已读；后续新版本需要再次展示。后台回报幂等，失败可重试，不出现需要用户手工标记的按钮。
- 自己通过网页或 MCP 产生的操作不进入自己的未读列表。
- 他人新增、编辑、删除、恢复观察记录，以及修改档案资料、负责人、业务状态、关闭或开启，形成新的未读动态；已读旧版本不代表读过新修改。
- 删除动态显示删除提示，不能通过未读摘要把已删除正文重新放回普通列表。
- 新账号从账号创建后的更新开始接收未读，既有档案仍可主动浏览；自己的已读操作不影响别人。
- 首版不做邮件、站外推送或在线聊天通知。

### 6.5 猎头管理与猎头账号

管理员可查看账号列表、创建账号、冻结账号、授予管理员权限。账号列表默认显示未冻结账号；“已冻结”范围可查看及解冻，筛选在分页之前完成。普通成员不显示后台入口，直接访问或通过 MCP 调用也必须被权限校验拒绝。

界面统一称个人入口为“猎头账号”，管理入口为“猎头管理”。成员仍是领域与权限模型中的主体，不新增一套账号角色。普通成员可在自己的猎头账号中上传、更换、移除头像和设置 QQ；不因此获得修改他人资料或角色的权限。

### 6.6 Agent 接入页

页面只提供简短使用说明和一个“复制提示词给 Agent”主要按钮。2026-09-09 用户明确修正：点击时自动创建当前成员的专用凭据，复制内容包含服务地址和完整 HTTP 认证配置，使无浏览器能力的 Agent 可直接接入。重复复制复用当前凭据，另一个 Agent 可单独生成；连接管理仍可撤销。临时/持久配置选择与新会话核验由 Agent 完成，不在页面展示多步骤技术教程。业务规则和任务指南由 MCP 提供，不倾倒到首次消息中。提示词见 [Agent 接入提示词](./agent-onboarding-prompt.md)。

个人凭证的创建、命名和撤销放入猎头账号的连接管理，接入流程需要本人授权时再引导打开；复制提示词不含秘密。当前前端原型没有正式 MCP 地址，复制内容明确这一边界，不模拟连接成功。

已确认：首版使用 Codex 验证接入和完整业务操作。首次提示词要求 Agent 在用户尚未选择时询问是否需要持久配置；已明确选择则沿用。持久配置分别核验客户端设置、持续可用的认证来源和新会话连通性，不把本次会话可用或配置已保存当作跨会话验证完成。接入后由 MCP 提供系统用途和业务指引；已有任务就直接接续。其他客户端接入细节由开发者处理，不逐项对齐。

完整接入提示词携带本次专用凭据，仅供用户交给要授权的 Agent；不在常态界面展示认证值、不放入公开仓库。Agent 不复述凭据，只保存到客户端支持的私有认证或配置位置。剪贴板失败时可选中同一份正文复制。

### 6.7 视觉要求

已确认：所有页面都要有审美，包括登录、后台、详情、空列表、错误反馈和接入说明。

建议采用适合长时间阅读的内部资料工具风格：清晰的字体层级、克制的状态色、稳定的间距、足够宽的正文区域、舒适的图片预览。人物与组织保持统一设计语言，记录内容优先于装饰。

已确认的视觉方向：现代化左翼、扁平化，吸收构成主义的几何构图与排版语言。首版必须简洁，逐一区域设计结构、层级、间距与交互；红黑白作为当前探索方向，避免复古做旧、书卷气、大面积装饰和过多粗重元素。先形成可靠的界面骨架，暂不添加口号；后续整活形式另行设计，不预设必须使用口号。

已确认：先在已确定风格内使用多张生图灵感稿探索具体艺术设计和排版，由开发者提炼统一方案，再实现前端交互原型；此项按用户最新建议替代之前不做原型的安排。不依赖生图表达准确业务状态或功能细节，业务行为以本 PRD 为准。桌面采用宽侧栏，手机采用全屏详情，核心操作均可完成。具体设计约束见 [首版设计说明](./design/README.md)。

头像纳入首版：人物与猎头账号都可以上传头像，展示优先级为“有效上传图 → QQ 头像 → 默认形象”。组织为“有效上传图 → 默认组织形象”，不使用 QQ 头像。上传图存在时不被 QQ 自动覆盖；移除或无法读取后尝试 QQ，再失败才显示默认图。人物多条 QQ 默认使用联系方式顺序中的第一条有效 QQ；可调整顺序或指定来源，不进行身份归并。人物与组织使用专门设计、有辨识度的默认形象，禁止使用首字/姓氏替代。QQ 缓存采用 24 小时新鲜期、过期访问刷新，失败保留旧缓存；缓存刷新不产生观察动态或改变活动排序。所有上传头像遵守私有图片访问；人物和组织上传也遵守档案关闭锁定规则。

字体使用本地提供的中文无衬线字体。第四版阅读基线：桌面观察正文 21px、列表摘要 19px、主要操作 18px；手机正文 19px、摘要 18px、状态与负责人至少 15px。适度增加字重、对比和间距，名称维持清晰层级，不靠压小辅助文字塞入内容。

列表上部显示状态与当前负责人/关联成员，摘要下方固定显示未删除观察记录条数和更新时间，不用负责人替换条数。登录页只保留一处品牌、账号与密码输入、登录按钮；不重复堆叠系统名、标题、说明和占位提示。原型提示只用一句，正式页移除。

### 6.8 标签展示与标签库

优先保证电脑端体验，保持已确认的字号和视觉方向。列表最多展示 3 个重点标签及其余数量，详情按类别展开全部可见标签，并能查看描述、依据和确认时间；未指定重点时使用稳定顺序，不自动给人物排序或评分。

添加先搜索复用，再按需创建类别和有描述的新标签。独立标签库入口可切换人物/组织库，维护定义并查看绑定影响。标签筛选与既有筛选组合，同类选项为“或”、跨类为“且”。同类同色并保留文字，不靠颜色单独传达含义。绑定修改产生档案动态，公共词库澄清只产生词库历史，不批量制造未读。详见 [交互规则](./tag-system.md#6-电脑端交互与检索)。

## 7. MCP 与 Agent 行为

### 7.1 能力范围

已确认：Agent 通过 MCP 可以执行对应用户能够执行的全部业务操作，而不只是查询。

范围包括档案查询与创建、资料修改、状态和负责人变更、关闭和开启、观察记录查询与图文提交、按权限编辑、删除和恢复记录、查看历史、读取未读更新与在实际返回内容后确认阅读进度，以及当前成员有权执行的账号管理与个人账号操作。

标签操作同样纳入：检索复用、新建类别/标签、读取定义及绑定影响、增减绑定和维护依据、重点设置、按标签检索，以及权限内的定义维护、合并与停用。工具区分“创建标签”“绑定标签”“移除绑定”“修改公共定义”，不能混成一个有隐式副作用的命令；完整职责见 [MCP 标签契约](./tag-system.md#7-mcp-业务契约)。

### 7.2 身份与规则

建议网页与 MCP 共用同一套业务规则和权限检查。每个 MCP 操作归属于一个已认证的成员账号，并记录来源；Agent 不获得独立的超级权限。

关闭档案的限制、作者编辑／删除／恢复限制、管理员限制，同样适用于 MCP。冻结账号后，其 MCP 操作也应失效。

### 7.3 图片

图片应纳入 Agent 创建观察记录的正式能力。建议流程是先上传图片并获得附件标识，再在提交观察记录时引用附件。Agent 本机文件路径不能直接作为其他成员可浏览的图片地址。

具体采用 MCP 上传工具、短期上传地址或其他协议，在技术验证中确定。需要验证网页、MCP 客户端、附件存储与历史版本之间的完整路径。

首版以 Codex 实测“配置接入 → 上传图片 → 创建图文观察记录 → 网页查看”的完整路径，并验证与网页一致的查询、编辑、删除、恢复、关闭、开启及管理员权限。实现完成前，以上属于验收目标，不表示已经完成兼容性验证。

### 7.4 服务内指引与 Agent 使用体验

首次提示词仅承担接入职责。系统用途、对象区别、状态与负责人、记录和图片、标签复用与依据、权限和错误恢复等业务指导迁入 MCP，通过简短入口、任务指南、工具说明和当前结果按需提供，不能只依赖最初聊天。服务内容可重新获取，不等于模型永远记得；权限仍由服务端执行。

MCP 的当前主要价值是压缩：成员直接提供聊天等材料，Agent 结合已有档案主动识别并补充观察记录、增减标签，必要时创建有描述的新标签。明确的材料整理入库任务包括这些相关动作，不要求成员逐项点名；意图不清时主动提出具体整理方案。观察保留事实、时间、归属和背景，标签提取有依据的特征，不因新材料没提旧标签就移除。设计见 [MCP 的 Agent 使用体验](./mcp-agent-experience.md)及 [Agent 使用指南](./mcp/agent-guide.md)。

首版留存外部 Agent 到达 MCP 的请求、业务参数和执行结果，并尽可能关联一次用户任务，以实际数据决定后续优化。用户原始提问与聊天只有 Agent 传入才可取得，不能把工具频次直接当作需求频次。请求内容属于私有业务数据，排除凭证，保持来源权限和到期清理。详见 [请求留存方案](./mcp-request-data.md)；当前尚未启用采集。

20. 作为成员，我希望观察记录比系统事件更醒目，并可单独筛选，以专注阅读材料。
21. 作为成员，我希望逐条查看未读更新并跳转原处，以补齐上次访问后的信息。
22. 作为管理员，我希望创建和冻结账号，以控制内部访问资格。

- 优先采用 Cloudflare serverless 服务。
- 已确认的上线要求：中国大陆成员无需使用代理即可正常访问网页并完成核心操作。
- GitHub 更新后自动部署。开发默认值：main 分支通过必要检查后部署生产环境，开发分支不覆盖生产；测试使用独立数据，部署回退不得通过清空真实数据实现。具体连接方式、迁移顺序与回退操作在技术设计中落实。

域名与访问方案：用户已提供自有域名 dapaidang.org，已通过现有本机 Wrangler 授权调用 Cloudflare API，确认该域名位于可访问账号下且 zone 状态为 active。用户已确认正式入口采用 scout.dapaidang.org，无需继续查询其可用性；正式入口尚未绑定，正式应用尚未部署。本次仅部署了隔离技术探针，结束后已删除临时资源及域名绑定。

若采用 Workers Custom Domain，在有效的 Cloudflare zone 中绑定域名时，Cloudflare 可自动建立对应 DNS 记录并签发证书，见 [官方自定义域名文档](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)。DNS 配置完成只说明域名接入完成，不代表大陆网络可用性已经验收。本次账号连接检查通过环境现有代理完成，不作为大陆无代理访问验证。

上线前需在成员实际使用的大陆无代理网络中验证登录、列表、记录读写、图片上传和查看；覆盖可获得的不同运营商网络并记录测试条件和结果。Cloudflare 官方说明跨境访问存在延迟和可靠性问题，见 [China Network 概述](https://developers.cloudflare.com/china-network/)。Cloudflare 是优先方案，实际访问结果决定是否满足上线要求；若不满足，调整部署方案后重新验证。本次已取得大陆联通无代理访问临时域名和业务探针的证据，但正式网页登录及跨运营商验收尚未完成，详见[验证报告](./technical-validation.md)。

开发默认值：字体、脚本和核心界面资源随应用提供，避免核心操作依赖额外的公共资源域名。MCP 的验收仍使用成员实际运行 Codex 的环境，不把网页无需代理的要求扩大为第三方 Agent 服务本身的网络承诺。

建议的职责划分：账号与鉴权、档案与状态规则、观察记录与附件、历史与未读、网页界面、MCP 入口。网页和 MCP 调用同一业务层，避免规则分叉；不预先拆为多个独立服务。

首轮技术选择与证据已写入[技术方案](./technical-design.md)和[验证报告](./technical-validation.md)。产品要求以本 PRD 为准，探针通过的路径与待实现的生产功能分别列明。

内部访问边界同时覆盖网页、业务接口、MCP 和图片附件；公开源码或知道一个图片地址不赋予读取权限。图片存储与传输方案须维持这一边界，具体机制在技术设计中落实。

## 10. 验收与验证方案

建议主要在已认证的业务接口边界验证可观察行为，另用少量网页与 MCP 端到端场景验证入口可用性。当前没有既有测试先例；具体测试边界待技术设计时确认。

| 验收场景 | 预期行为 |
| --- | --- |
| 普通成员修改他人的观察记录 | 网页和 MCP 均拒绝，原内容不变 |
| 作者或管理员修改开启档案的记录 | 更新成功，旧版本及修改人、时间可追溯 |
| 普通成员删除或恢复他人的观察记录 | 网页和 MCP 均拒绝，即使该成员曾参与相关档案维护 |
| 作者删除或恢复自己的记录，管理员删除或恢复任意记录 | 开启档案中操作成功；保留原始作者、内容版本与关联图片，历史记录操作人和时间 |
| 管理员编辑或删除了一条记录，原始作者恢复该记录 | 在档案开启时允许恢复；作者权限不因管理员操作而转移 |
| 关闭档案中的记录被尝试删除或恢复 | 包括作者和管理员在内，网页和 MCP 均拒绝 |
| 档案已关闭，任何成员尝试修改或新增内容 | 网页与 MCP 均拒绝；必须先重新开启 |
| 成员将开启档案切换到该实体类型的任一合法业务状态 | 不检查前置状态或顺序；记录变化，目标为关闭类状态时同时关闭 |
| 人物进入已入伙或已弃用，组织进入已弃用 | 业务状态更新与关闭一起完成，历史明确包含两种变化 |
| 成员因失联或不再关注而弃用档案 | 统一使用已弃用并关闭，不要求单独填写关闭原因；需要说明时可在关闭前提交普通观察记录 |
| 成员重新开启档案 | 恢复可维护状态，历史包含已开启事件和时间 |
| 多名负责人被新增、替换或移除 | 当前关联正确，历史保留前后变化 |
| 档案新增或编辑观察记录 | 档案按新的活动时间参与列表排序 |
| 成员只查看档案或自动更新阅读进度 | 档案活动时间和排序不因此改变 |
| 时间线包含大量系统事件 | 观察记录仍醒目，且可只查看观察记录 |
| Codex 完成 MCP 接入并创建含图片的观察记录 | 按页面复制说明完成接入；网页中可正常查看提交的文字和图片，作者与操作来源正确 |
| 成员尚未选择配置寿命，或进入不含最初提示词的新会话 | 先询问临时/持久选择；保存与验证分别报告；连接后可从服务取得实际能力和业务指引 |
| 成员要求把聊天材料整理入档 | 主动补观察及有依据的标签增减/创建，保留时间和信息归属；不要求逐项点名，不因遗漏提及就删除旧标签 |
| 一次材料整理产生多次查询、写入和重试 | 实际调用、明确关联的任务及业务结果分开统计；原始提问未传入时标为未知 |
| 管理员查看请求详情或执行到期清理 | 不返回凭证或越权来源；清理分析副本不删除正常观察、历史和附件 |
| 管理员冻结账号 | 阻止该账号后续网页与 MCP 访问，已有会话与凭证失效，历史作者归属保留 |
| 普通成员直接调用管理员操作 | 服务端拒绝，不依赖是否隐藏按钮 |
| 未登录访问档案、记录、历史版本或附件地址 | 不能读取内部内容；网页、业务接口与 MCP 的访问规则一致 |
| 成员 A 实际阅读更新 | 自动推进 A 的阅读进度，无手工已读按钮；不影响 B；后台或未展示内容不被清除，新版本仍为未读 |
| 普通成员访问他人已删除的正文、版本或图片地址 | 网页、MCP 与图片路由均不返回具体内容；作者和管理员可读；恢复后正常可见 |
| 人物/猎头账号上传头像与设置 QQ，移除上传图或加载失败 | 上传图优先，其次 QQ，再回退默认图；组织仅上传图或默认图；不使用首字 |
| 冻结或降权操作将导致没有未冻结的管理员 | 拒绝操作，账号和角色保持原状 |
| 公开仓库与部署检查 | 仓库中无真实业务资料、图片、账号凭证；部署能访问独立数据存储 |
| 中国大陆成员使用正式域名、在不使用代理的网络中访问网页 | 能登录、浏览和维护档案、上传及查看图片；记录实际运营商与测试结果，DNS 生效不能替代业务操作验证 |

标签验收须完整覆盖 [标签验收表](./tag-system.md#8-验收与首版边界)，包括跨库、重名、并发影响变化、合并、关闭快照和来源删除后的所有读取入口；既有探针结果不表示这些新增能力通过。

视觉验收应覆盖登录、列表、详情、标签库、编辑、关闭档案、后台、接入页，以及加载、空白和错误状态；优先检查电脑端的阅读和常用操作，再确保窄屏核心功能可用。

以上作为首版验收依据；实现方案变化时同步更新相关用例，但不能在未说明的情况下降低已确认要求。

## 11. 范围边界

已明确不包含自助注册，公开仓库不意味着档案对外公开。

建议第一版暂不包含：自动抓取外部平台、自动识别人脸或关联身份、自动给人物评分或决定招录、复杂组织层级和逐档案访问控制、对外消息发送、复杂审批流、实时协同编辑。用户当前未请求这些能力。

第一版不提供永久清除观察、整张档案或账号。整张档案支持管理员可恢复删除，业务已弃用仍表示关闭；账号沿用冻结并默认隐藏，保留历史身份。观察记录按已确认权限可恢复删除。

简单未读功能纳入首版；如需因具体实施成本调整范围，再向用户说明取舍。

## 12. 对齐结论与技术验证

目前没有必须再次向用户提问的 P0/P1 产品规则。状态、权限、记录删除和恢复、标签系统方向、MCP 验证目标、大陆访问要求均已明确，其余产品默认值已写入对应章节。本轮标签预置词汇、普通成员可维护定义而合并/停用归管理员、重点上限 3 个、筛选逻辑均是可逆默认值；关闭快照与来源读取规则延续已确认权限，不需要新增审批流程。

后续正式实施与验证由开发者完成：

1. 确定应用、数据库、私有附件存储、鉴权和 MCP 的实现方式，确认所需 Cloudflare 权限、资源限制及费用；涉及实际购买或显著预算取舍时提供具体方案。
2. 用 Codex 验证接入、图文写入与权限一致性，补齐提示词中的配置步骤和工具名称。
3. 按已确认的 scout.dapaidang.org 落实正式域名绑定，实测大陆无代理网络的完整访问路径；现有账号连接成功不能替代该项。
4. 在已经审阅的视觉方向和前端原型内补充标签交互，优先验收电脑端的列表重点、详情依据、标签库与影响预览；现有长记录、多图和窄屏体验继续保留。
5. 明确数据备份与恢复方式、自动部署检查、数据迁移和回退步骤，真实数据始终与公开仓库分离。

本 PRD 是产品基线，不代表正式应用已实现或上线。首轮验证、技术方案与原型已完成；后续实施切片已发布为 GitHub #1–#14，见[实施任务](./implementation-issues.md)，统一归入 v0.1.0。

### 文档修订 1.2 · MCP 信息收集补充

工具 schema 中“非必填”只表示允许资料暂时未知，不意味着 Agent 应忽略。创建/整理档案前，主动检查提供的材料中的联系方式、QQ、关联成员、来源链接、图片，并在已授权范围内填写。对有用但缺失的信息，用简短追问或完成后的补充提醒收集，不机械逐字段盘问。工作状态负责人缺失必须在写入前询问，不擅自选择；其他状态允许先保存，再提示可补关联。以上规则由服务内任务指南、工具描述和相关结果提供，不能只依赖首次提示词。

## 2026-09-09：整张档案删除与恢复（Issue #20）

仅管理员可以删除、查看已删除档案及恢复。开启或关闭档案均可删除；从列表、搜索、未读、范围统计、草稿列表与标签公共维护影响范围移走，所有内容、图片和历史仍保留。其他成员即使是观察原作者，也无法通过旧详情、历史或图片入口读取。

回收内容只读，禁止资料、状态、头像、标签、观察和草稿写入；恢复后保留原业务状态、各状态成员绑定和原作者，不自动重新开启，不恢复单独删除的观察。开启档案删除时冻结标签词义，恢复时回到当前定义；已关闭档案始终保留原关闭快照。删除/恢复事件记入历史，旧阅读票据失效，旧标签维护预览需要重新核对。

网页在编辑档案内部提供删除入口，关闭档案直接提供删除按钮；管理员工具菜单提供“已删除档案”，复用人物/组织列表与只读详情。所有操作均保留明确对象确认、版本冲突重读及原请求重试。完整约束见 [ADR 0010](./adr/0010-archive-trash-and-frozen-member-lists.md)。
