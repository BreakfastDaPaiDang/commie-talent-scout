## S1 · 管理员通过真实密码登录隔离环境

### What to build

在独立测试环境部署正式应用的最小入口。维护者私有初始化管理员，管理员用临时密码登录、更换密码后进入空工作台，再退出。提供统一的登录、错误和窄屏页面。

### Acceptance criteria

- [ ] 使用真实 D1 密码记录与服务端会话；按已验证 scrypt 参数保存随机盐和算法版本，不沿用探针预置 Cookie。
- [ ] 首登改密、错误密码、过期会话、退出、未认证访问及跨来源 Cookie 写入均有行为验证；未登录不能访问业务内容或图片。
- [ ] 密码计算前限速，验证昂贵 KDF 并发上限；在真实 Worker 上记录 CPU、延迟和并发内存表现，确认账号套餐再决定上线配置。
- [ ] 初始化入口不能被普通请求重复利用；秘密只位于私有配置，测试环境与生产数据隔离。
- [ ] 登录页与空工作台落实已审阅的构图，桌面和窄屏可操作；检查通过后可部署测试环境。

### Blocked by

无，可先开始。

## S2 · 成员创建 MCP 凭证并用 Codex 确认身份

### What to build

Agent 接入页只保留短说明和复制提示词按钮，成员把提示词交给 Codex 完成连接检查及配置，并确认当前身份。需要本人授权时引导到猎头账号的连接管理，创建、命名和撤销个人凭证。MCP 与网页共用身份业务模块。

### Acceptance criteria

- [ ] 凭证明文只显示一次，服务端仅存哈希；列表不重新展示秘密，撤销即时影响后续调用。
- [ ] 无状态 Streamable HTTP 的每请求身份检查有效，未认证连接拒绝；真实 Codex 发现工具并调用 `whoami` 成功。
- [ ] 复制说明包含实际服务地址、环境变量配置、关闭/作者权限、幂等要求与后续图片的本机上传前提。
- [ ] 接入页面、认证错误和撤销反馈完整，凭证不写入普通应用日志、提示词模板或公开仓库。
- [ ] 接入主页面没有技术教程、配置代码块或凭证管理表单；复制成功有反馈，剪贴板不可用时提供可选择复制的正文。提示词先检查已有连接，不索要聊天中的明文秘密。

### Blocked by

S1。

## S3 · 人物与组织档案的创建、查询和资料维护

### What to build

成员在人物/组织列表创建档案、查看详情并维护名称、联系方式和链接，不设置别名或简介；Codex 可执行同样操作。先交付分页列表和空观察区。

### Acceptance criteria

- [ ] 人物、组织保持各自类型；名称、联系方式和可选字段按 PRD 校验，QQ 字符串可保存，人物与组织使用不同的趣味默认头像。
- [ ] 两个入口使用同一业务命令，成员可编辑任一开启档案；冲突返回明确结果，重试不重复创建。
- [ ] 真正变化才更新活动时间及审计事件，无变化保存不生成历史；事件包含操作者、时间与入口来源。
- [ ] 列表与详情有分页、加载、空白、失败及重试状态；窄屏在列表与详情之间正常返回。
- [ ] 列表上部显示当前负责人/关联，底部始终显示观察记录条数与更新时间；长名字与窄屏不相互挤占。
- [ ] 联系方式可直接复制；人物/组织各自保留查询条件和选中档案，切换成员不混用偏好。

### Blocked by

S2。

## S4 · 状态、负责人、关闭与重新开启

### What to build

成员从网页或 Codex 自由选择合法业务状态，通过可搜索下拉为当前状态选择多人绑定，关闭档案后只读，显式重新开启后恢复维护。详情展示完整变化事件。

### Acceptance criteria

- [ ] 使用 PRD 中人物/组织的准确状态集合，无顺序限制；状态与关闭状态始终一致。
- [ ] 人物三个工作状态、组织“组织交流”必须选至少一名负责成员，网页和 MCP 同样校验；其他状态可选关联，不默认调用者。
- [ ] 绑定按状态留史，只展示当前状态的成员；搜索多选适应十几名成员，冻结成员已有归属按 PRD 处理。
- [ ] 包括管理员在内不能修改关闭档案；普通资料更新不能绕过显式重新开启。
- [ ] 并发关闭与修改不会产生关闭后成功写入；状态、负责人、开启/关闭事件与内容原子提交。
- [ ] 长状态名称、多人名字和事件密集时不遮挡主要操作。

### Blocked by

S3。

## S5 · 文字观察记录与可追溯的编辑

### What to build

成员通过网页或 Codex 发布短观察和长文字，作者或管理员可编辑，其他成员只读；旧版本可查看，列表显示最近记录摘要，详情以观察内容为主。

### Acceptance criteria

- [ ] 创建、编辑、版本和事件原子写入；作者身份不随管理员编辑改变，记录创建时间与修改时间区分。
- [ ] 同一版本并发编辑只允许一次成功；幂等重试不多写，空白正文被拒绝，无变化保存不新增版本。
- [ ] 关闭锁在记录操作事务内复核，网页隐藏按钮与 MCP 错误均符合相同权限。
- [ ] 全部动态与仅观察记录切换正确；内容活动排序、近期摘要和历史版本分页正确。
- [ ] 长文、换行及阅读宽度经过浏览器检查；保存中、失败重试可用。未发布观察按成员和档案保存，跨档案和切页不丢失，列表提示草稿；发布成功才清除，失败保留。正式保存机制明确刷新/退出行为，原型内存演示不作为持久化验收。
- [ ] 返回档案恢复阅读位置；搜索与未读的显式定位优先于位置恢复，窄屏同样有效。

### Blocked by

S4。

## S6 · 网页与 Codex 提交多图记录并查看旧版本

### What to build

成员选图或由 Codex 上传本机图片，创建图文/仅图片记录；编辑附件形成新版本，历史仍能查看之前的图片。

### Acceptance criteria

- [ ] 票据绑定成员、认证 epoch、档案、字节数、类型和哈希，过期/重复/不匹配上传拒绝。
- [ ] PNG/JPEG/WebP 实际类型、10 MiB 单图和每条 10 图上限由服务端校验；大图与多图不会无界占用内存。
- [ ] R2 不公开，图片路由每次鉴权；记录当前版本与历史版本引用正确，不因移除当前附件丢失旧图。
- [ ] 上传失败与业务提交失败可重试，暂存清理不删除任何历史版本引用对象。
- [ ] 在正式网页和真实 Codex 之间完成上传、写入、网页读取、编辑附件和查看旧版本的联合验收。
- [ ] 多图预览、进度、失败、移除和窄屏大图操作可用。
- [ ] 人物和猎头账号支持上传、更换、移除头像，上传图优先于 QQ 备用图，再回退默认形象；组织只有上传图与默认图。本人头像写入及私有读取鉴权正确，跨主体票据拒绝；同域 QQ 代理采用 24 小时缓存，上传图有效时不请求或被 QQ 覆盖，关闭/冻结策略与来源切换正确。

### Blocked by

S5。

## S7 · 观察记录删除、恢复及历史保留

### What to build

作者删除或恢复自己的记录，管理员处理任意记录；普通列表隐藏已删除内容，已删除视图允许有权成员恢复，内容与图片历史保留。

### Acceptance criteria

- [ ] 删除是可恢复状态变更，正文、版本和图片引用均保留，其他成员不能删除或恢复不属于自己的记录。
- [ ] 删除后的正文、历史版本、附件及旧图片地址仅原作者/管理员可读取；查询、搜索、未读、HTTP、MCP 不泄露具体内容，仅允许无正文的操作元数据。
- [ ] 管理员删除后原作者仍能恢复自己的记录；关闭档案中任何人均不能删除/恢复。
- [ ] 并发删除/恢复、重复请求和版本冲突不会制造重复事件或覆盖编辑。
- [ ] 网页、MCP、普通列表摘要、已删除视图与历史展示一致，错误后可继续操作。

### Blocked by

S6。

## S8 · 搜索筛选与成员各自的未读更新

### What to build

成员按名称、联系方式、观察正文搜索，并使用全部/我负责/有未读范围与高级组合筛选；打开对应内容后自动推进个人阅读进度，Codex 在实际返回内容后确认同一套阅读状态。

### Acceptance criteria

- [ ] 搜索、组合筛选、清除和游标分页正确，删除记录不进入普通正文检索与摘要。
- [ ] 未读排除自己动作及账号创建前事件，编辑会产生新更新；一名成员的已读不影响其他成员。
- [ ] 无手动已读按钮；对应内容在前台实际展示后自动确认，不清除未加载、屏幕外或失败内容，后台暂停；长卡片以正文起始区域展示为边界。
- [ ] 阅读进度按事件及版本幂等写入，不改变活动排序，失败可重试。
- [ ] 未读跳转定位到相应事件/记录，删除或已关闭目标能给出正确上下文。
- [ ] 搜索旧观察显示命中摘要并定位高亮；“我负责”只按当前工作状态绑定计算，搜索与筛选记忆按成员及页面隔离。
- [ ] 本次未读队列在逐条阅读时保留已阅条目位置，全部读完显示完成状态；下一处未读能跨人物/组织继续，显式跳转不受原列表筛选限制。
- [ ] 以代表性数据验证列表请求量、分页边界和查询耗时，网页空结果与读取失败反馈完整。

### Blocked by

S5；与 S7 合并验收删除记录的查询行为。

## S9 · 管理员创建账号、重置密码、冻结和授权

### What to build

管理员从账号页或对应 MCP 工具创建成员、发放临时密码、重置密码、冻结/解冻和调整角色。成员首登改密后使用自己的身份。

### Acceptance criteria

- [ ] 管理动作由服务端校验并审计，普通成员不能调用；账号标识唯一、密码不回显或写入日志。
- [ ] 重置和冻结推进认证 epoch，旧网页会话、已连接 MCP、图片访问与上传票据全部失效；解冻不复活旧凭证。
- [ ] 事务内保护至少一名未冻结管理员，并发自我降权/冻结只能允许不破坏该约束的操作。
- [ ] 冻结不改变既有作者归属；已有负责人显示不丢失。
- [ ] 账号列表、创建、改密、冻结和最后管理员冲突均有明确页面反馈，敏感操作后刷新当前用户状态。

### Blocked by

S2；图片与记录撤销联合验收在 S6/S7 完成后执行。

## S10 · 正式域名上线、自动部署与恢复验收

### What to build

将完整业务部署到正式入口，main 检查通过后自动发布。以真实成员网络验证业务闭环，并在隔离环境演练数据恢复，让维护者能持续更新且保留业务材料。

### Acceptance criteria

- [ ] 确认套餐、域名占用和部署配置，使用项目所需权限的部署凭证；生产、测试、公开仓库数据边界明确。
- [ ] 自动部署串行执行检查、备份、兼容性迁移、部署和冒烟；失败能恢复代码服务，不以清空真实数据回退。
- [ ] 在隔离环境恢复数据库与图片引用，核对账号、记录版本、删除状态、附件、标签定义/绑定/依据、合并映射和关闭快照，记录恢复步骤与结果。
- [ ] 正式域名在大陆无代理网络中完成真实登录、列表、图文读写及图片查看，记录运营商、时段和结果；尽量覆盖其他成员网络。
- [ ] 完成正式网页 + Codex 权限/关闭/删除恢复/冻结/图片/标签维护闭环；失败项修复后再视为上线完成。
- [ ] 页面包含必要加载、错误、空白和窄屏状态；日志脱敏、用量告警与 CPU 限制可用。

### Blocked by

S7、S8、S9、S12。

## S11 · 成员与 Agent 复用/创建标签并维护有依据的绑定

### What to build

成员在人物或组织详情内检索对应词库，复用或按需创建类别及有描述的标签，维护绑定和依据；列表显示少量重点，详情分组展开，Codex 能完成同一路径。初始化 [人物 34 项、组织 31 项词库](./tag-catalog.md)，不自动给任何档案绑定。

### Acceptance criteria

- [ ] 人物/组织分库，类别与标签使用稳定 ID 和唯一约束；格式、长度、描述、重名及跨库规则由共享服务执行，并发创建不重复。
- [ ] 添加标签优先搜索描述再复用，无命中可就地新建；手工绑定保持轻量，Agent 从观察整理必须引用实际记录/版本或明确独立材料。
- [ ] 同档案同标签最多一个当前绑定；增减、依据修改与重点设置留史、幂等，批量整理只产生一条汇总事件，不重复顶起活动。
- [ ] 列表最多 3 个重点及余项数量，未指定重点时稳定排序；详情显示定义、依据和确认时间；同类同色但不只靠颜色识别，优先验收电脑端阅读和操作。
- [ ] 关闭事务记录定义/绑定快照，关闭时所有成员均不能修改绑定；重新开启处理定义差异，不静默迁移停用项。
- [ ] 查询绑定及来源时复核当前成员；资料缺失、无依据和来源不可读均有正确行为，不把受限依据复制为公共标签描述。
- [ ] 真实 Codex 完成查库、复用/创建、添加/移除绑定及失败重试，网页结果一致；记录新能力的实际验证证据。

### Blocked by

S5；与 S7/S12 联合完成来源删除后的全入口读取验证。

## S12 · 标签筛选、共享定义维护与完整历史权限

### What to build

成员按标签检索档案，在标签库查看定义与绑定范围，更名或澄清前查看影响；管理员可合并重复项、停用/恢复。网页与 MCP 共用影响预览、版本控制和来源可见性，保留关闭快照、旧词义和迁移历史。

### Acceptance criteria

- [ ] 标签筛选同类“或”、跨类“且”，与既有状态/负责人/搜索组合；分页、数量、空结果与 MCP 语义一致，隐藏绑定不能影响匹配或统计。
- [ ] 标签库支持定义与描述检索、绑定计数与分页列表、开启/关闭分组、定义历史；所有结果按调用者权限过滤。
- [ ] 更名、释义、类别调整与合并/停用前返回实际影响与差异；执行复核定义和绑定集合版本，过期预览拒绝，不能将预览当成授权。
- [ ] 普通成员可创建/澄清共享词汇，合并/停用/恢复仅管理员；冻结后网页与 MCP 都立即拒绝。
