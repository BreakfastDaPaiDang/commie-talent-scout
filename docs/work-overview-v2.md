# 工作总览开发版

基线：正式版回滚提交 b2a1a21（#116 / #117）。不导入或复用旧 PersonnelMap、InternalResources、InteractionGraph 的组件、接口、数据投影或资源目录；既有档案、观察、任务与身份基础设施继续使用。开发版单独分支，不自动覆盖已回滚的正式站。

## 已确认的工作规则

- 首要目标是辨认需要联系和更新档案的人，以及本次工作由谁负责。
- 容器是主表中的单个色块。阶段是个人的经历时段，不是资源或组织。
- 实际业务状态切换决定分段；回滚在真实切换时刻重新进入先前类型，历史仍按时间保存。观察和实际状态事件是事实来源。
- 每人从自己的首段经历起点开始，全表统一每天宽度，不把每行拉伸到相同总长。
- 颜色绑定经历类型，接触红色、审核黄色，所有图例、容器、资源图和预测图一致。
- 社内承接资源是社内实际拥有、能接收、安排或支持新人的群聊、工作组、项目或支持条件。资源调动指同一资源的用途替换；保留原用途再新增属于用途扩展。
- 阶段缺口由人明确填写“为了完成什么工作，目前缺什么”，不从资源数量自动推断。
- 资源图可切换数量和容量模式；角度表达资源个数，容量模式以环带厚度表达可接收人数。多用途资源按用途参与统计，未知容量不作零。
- 仅新增观察重置30天计时，修改基础资料、编辑或恢复旧观察不算新增；无观察从建档开始，删除最新观察回到最近有效观察。
- 预测显示未来每日仍待跟进人数：满30天后逐日继续计入，直到新增观察；每人每天只计一次。当前积压包含在未来预测中，不重复相加。
- 现有开启跟进任务有唯一明确负责人时展示该人，无责任关系进入待分派；已完成任务负责人不自动续任，多负责人冲突不得猜测。
- 复用现有任务创建、领取和指派接口，在任务详情补齐管理员指派入口；显式跟进关系不从任务标题或标签猜测。已有开启跟进任务时复用，避免重复生成。
- 开启人员纳入，组织单独筛选和计数，关闭/删除排除；不引入“淡出”概念。

## 界面

沿用已讨论的三图布局；主表顶部、资源与预测下方并列，桌面以4:3视窗验收，窄屏逐个堆叠。主表容器采用浅箭头、柔和纯色和统一文字层次，文本直接位于容器内；保留比例，短时段通过缩放和详情可读，不伪造最小天数。

共享组件位于 app/ui/WorkOverview.tsx，真实页面和开发预览都引用同一组件。编辑资源、缺口和阶段落实时使用完整表单，保存后读回真实接口。所有新写入具备权限、版本、事务和幂等收据。
