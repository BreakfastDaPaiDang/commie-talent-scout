# 工作总览开发版

基线：正式版回滚提交 b2a1a21（#116 / #117）。不导入或复用旧 PersonnelMap、InternalResources、InteractionGraph 的组件、接口、数据投影或资源目录；既有档案、观察、任务与身份基础设施继续使用。开发版单独分支，不自动覆盖已回滚的正式站。

## 已确认的工作规则

- 首要目标是辨认需要联系和更新档案的人，以及本次工作由谁负责。
- 容器是主表中的单个色块。阶段是个人的经历时段，不是资源或组织。
- 实际业务状态切换决定分段；回滚在真实切换时刻重新进入先前类型，历史仍按时间保存。观察和实际状态事件是事实来源。
- 主表仅显示当前未正式入社人员，组织仍单独查看；每人从首段经历开始，当前可见列表最长一行自适应可用宽度的87.5%，右侧保留至少1/8空白，其他行共用同一时间比例。窗口、筛选和时长变化时重新适配，不固定每天像素、不横向滚动。
- 颜色绑定经历类型，接触红色、审核黄色，所有图例、容器、资源图和预测图一致。
- 社内承接资源是社内实际拥有、能接收、安排或支持新人的群聊、工作组、项目或支持条件。资源调动指同一资源的用途替换；保留原用途再新增属于用途扩展。
- 阶段缺口由人明确填写“为了完成什么工作，目前缺什么”，不从资源数量自动推断。
- 资源图可切换数量和容量模式；角度表达资源个数，容量模式以环带厚度表达可接收人数。多用途资源按用途组合单列、混色，每项资源与容量只计一次，未知容量不作零。
- 仅新增观察重置30天计时，修改基础资料、编辑或恢复旧观察不算新增；无观察从建档开始，删除最新观察回到最近有效观察。
- 预测显示未来每日仍待跟进人数：满30天后逐日继续计入，直到新增观察；每人每天只计一次。当前积压包含在未来预测中，不重复相加。
- 现有开启跟进任务有唯一明确负责人时展示该人，无责任关系进入待分派；已完成任务负责人不自动续任，多负责人冲突不得猜测。
- 复用现有任务创建、领取和指派接口，在任务详情补齐管理员指派入口；显式跟进关系不从任务标题或标签猜测。已有开启跟进任务时复用，避免重复生成。
- 开启人员纳入，组织单独筛选和计数，关闭/删除排除；不引入“淡出”概念。

## 界面

最新布局为下文“四图统一统计与周报”；原三图与提交统计合并，桌面以4:3视窗验收，窄屏逐个堆叠。主表容器采用箭头连接、加深纯色和统一文字层次，文本直接位于容器内；保留真实比例，短时段通过姓名入口和经历选择器查看详情，不伪造最小天数。

共享组件位于 app/ui/WorkOverview.tsx，真实页面和开发预览都引用同一组件。编辑资源、缺口和阶段落实时使用完整表单，保存后读回真实接口。所有新写入具备权限、版本、事务和幂等收据。

## 本轮调整

资源目录独立于人员筛选及阶段使用记录，资源可在没有用途和关联经历时单独创建。用途可选；未设用途资源仍保留在目录，图旁列出数量。删除资源通过版本校验和幂等命令，从当前目录、供给统计及新的选择项移除；历史使用引用和文字保留，并标记已删除。删除与停用是不同操作，旧表单不能覆盖已删除资源。

主表排除当前社员，30天待跟进预测仍覆盖所选范围的开启档案，保留对社员的跟进提醒。

仪表盘采用平整布局：图表无独立卡片外框，以留白和细分隔线组织内容；颜色仅保留在经历色块、图表及图例等业务表达上。天数按已满整天显示，不足一天显示“不足 1 天”；刻度均为整数，长度计算仍保留真实时长。

- 所有当前关联任务显示在详情。沟通跟进沿用既有同对象任务；具体工作可多项独立创建，不作为长期跟进责任依据。
- 白色资源仅由已提交、人事审核阶段、未填对接资源的观察人工登记，一条观察最多一项。补齐可选择已有资源或新建，多项来源指向同一实体只计一次；删除观察或关闭档案后不再显示相应白色占位，历史不抹除。

## 推荐闭环（2026-11-07，替代独立需求编辑）

用户确认将推荐作为侧栏的首要操作；人员主表更名为“入社进度”，时间分段规则不变。移除侧栏的“需要的帮助”独立编辑，原档案字段和历史数据保留，不自动转换为新观察。帮助需求直接记录在观察中，不另加必填表单。

当前经历侧栏首先显示基于最新观察的对接候选，可改选具体观察。首版是可解释的共同词匹配，不是语义模型，也不保证合适：来源是完整观察正文，资源用名称与说明、人物用当前可见且启用的标签、任务用标题/目的/交付。空依据不推荐，通用词不作为依据；明确的简单否定短语被排除。未知意愿、可用性必须确认，不从主题相近推断愿意参与。资源须启用、未删除、用途包含当前经历类型且容量不为零；容量未知可作为待确认候选。人物关闭/删除排除；任务须开启、未领取且未到期，候选只供协调，不自动领取原任务。

“安排对接”展开同一侧栏的小表单，确认标题、行动、负责人和期限。普通成员只能接给自己，管理员可指派其他有效真人账号。复用现有任务创建事务，一并保存来源观察及其内容版本、候选及版本、推荐理由、负责人和引用来源的任务评论。相同档案/观察版本/候选重复采纳复用原任务；请求响应不明保留参数和 request_id，先查收据再重试。采纳时比较候选内容指纹，标签释义等变化不能沿用旧推荐；观察、档案、候选、账号和权限变化在事务中校验，失败不留半个任务。采纳不自动改变资源占用、人员状态或完成原任务。

新对接任务使用既有任务领取/交付/重开生命周期，交付必须引用本轮新增观察；旧推荐来源不能代替行动结果。侧栏“对接进展”读回实际任务状态、负责人和交付结论；其他任务准确标为“该对象的未完成任务”，“拆分工作”改为“新建任务”，未宣称已有父子任务关系。

关联资源在侧栏可直接查看计划/已落实状态与说明，观察历史次级展开；历史经历不展示当前推荐，新增入口改为补记并要求发生时间。侧栏不再用重复的需求表单取代推荐。

验收：新增 SQLite 服务测试覆盖推荐过滤、权限、证据版本、幂等与完成回写；真实 HTTP 验证桌面/手机完整推荐表单、响应丢失恢复、来源绑定、原观察/资源编辑回归；历史原型与正式入口继续共用 app/ui 组件。仅开发分支，未合入或部署 main。
