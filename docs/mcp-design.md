# MCP 对接设计与验收

适用产品：v0.1.0，2026-09-08。本文记录待实现的技术承载要求；以 [材料压缩体验](./mcp-agent-experience.md)确定所需信息，再收敛正式工具。首次提示词只负责接入和临时/持久选择，业务指导由服务提供，硬约束由服务端保证。

前端采用共用的短复制模板；正式后台、完整 MCP、标签和请求留存尚未实现。现有探针仅提供技术参考，其局部改动不代表正式产品交付。产品内容见 [Agent 使用指南](./mcp/agent-guide.md)，连接入口见 [接入说明](./agent-onboarding-prompt.md)。

## 1. 已发现的问题

| 原状 | 对 Agent 的实际影响 | 设计要求（正式实现仍待交付） |
| --- | --- | --- |
| 复制正文包含状态、头像、标签和权限长清单 | 依赖某次聊天历史，压缩后可能丢失；两份复制正文已出现重复维护 | 首次提示词收敛为连接、配置范围和验证；前端使用独立文本模板 |
| 原探针只有简短工具描述，未返回服务级 instructions | 冷启动时缺少跨工具次序和能力边界 | 提供简短初始化指引；工具独立描述用途、前提、副作用和恢复入口 |
| 业务失败仅返回错误码 | 容易猜测原因、盲重试或为了写入自动重开 | 增加解释、恢复建议与是否可直接重试；无法区分的原因明确承认 |
| change_record 的 edit 省略 body 时会变成空串 | 一个漏参可能清空已有正文 | MCP 输入拒绝漏参编辑，以及携带正文的删除/恢复 |
| 成功结果只有 JSON 文本，缺少输出 schema 和风险注解 | 客户端难以可靠消费或判断读写副作用 | 工具提供输出 schema、结构化结果及注解；仍由服务端鉴权 |
| 一次会话连通即被当作完成接入 | 新会话可能缺服务器项，或缺本次终端中临时设置的令牌 | 分别检查配置、认证来源和新会话连通性 |

## 2. 分层职责

| 层 | 放什么 | 不承担什么 |
| --- | --- | --- |
| 首次复制提示词 | 服务地址、认证入口、是否持久配置、接入结果验证 | 不携带完整业务手册；不代替以后任务的授权 |
| MCP 初始化 instructions | 服务身份与能力边界、先确认身份、重要跨工具规则、指南入口 | 不倾倒 PRD，不假设所有宿主都会永久注入或始终记住 |
| 工具 description 与字段 schema | 何时使用、要哪些 ID/版本、可选字段的价值、会改变什么、常见下一步 | 不把权限藏在描述里；不要求 Agent 记住其他工具才知道本工具的危险副作用 |
| 可查询主题指南 | 档案、状态、观察、标签、图片、未读、错误恢复的流程与小例子 | 不要求每次调用前读取全部内容；不靠资源自动加载这一假设 |
| 工具结果和错误 | 当前环境/身份、版本、可见数据、实际完成范围、缺项、恢复建议 | 不返回空洞的“成功”，不把失败当空列表，不把推荐动作当授权 |
| 共享业务服务 | 身份、冻结、作者权限、关闭、标签来源权限、版本、事务、幂等 | 不依赖 Agent 自觉；也不声称能验证人的真实意图或材料真实性 |

MCP 服务中的指南是可重新取得的信息源，不是模型永久记忆。宿主可能按需发现工具、截断描述或丢弃历史；重要指引放在 instructions 开头和相应工具描述中，复杂规则用查询入口补充。首段自包含，Codex 的前 512 字符建议仅作为适配目标，不视为跨客户端协议保证。[Codex MCP 文档](https://developers.openai.com/codex/mcp/)

工具 schema、description、输出 schema、结构化结果与注解是 MCP 的不同机制；注解仅描述行为，不能授予访问权限。协议或 schema 错误与业务执行错误分开处理，客户端不能假定所有错误文本都是 JSON。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

正式实现由一份可加载的主题内容供指南工具和可选 resources 使用。resources/prompts 可增强宿主体验，但首版核心路径必须仅依赖 tools 也能完成，不能假设客户端会主动注入资源或选择 prompt。[MCP 生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)、[Resources 规范](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)

## 3. 接入与持久配置

1. 检查当前客户端、当前宿主及已有连接，核对实际服务 URL、环境和成员身份；仅名称相同不能当作正确连接。已有正确配置应复用，不制造重复服务器项或覆盖已有工具限制。
2. 若用户尚未选择，询问是否需要持久配置，说明持久配置供以后新会话使用；已明确选择则沿用。未得到选择时不擅自持久写入。临时连接只作用于当前会话，结束后明确说明其寿命。
3. 选择持久配置后，说明具体客户端及保存范围。无另行限定时建议该客户端的用户级私有配置；项目级仅在用户希望局限该项目时采用。配置选择不等于放宽审批、允许所有工具或切换成员身份。
4. 配置项和认证来源分别处理：保存了服务器地址，但令牌只存在于这次 shell 的环境中，仍不能认定以后可用。使用当前客户端支持的认证存储或持续可用的安全注入方式；服务实际支持 OAuth 时可采用其授权存储。现有产品方案仍是个人凭证，不能因为客户端支持 OAuth 就虚构本站支持 OAuth。
5. 只修改对应服务器项，保留其他设置和凭证；同名冲突、环境不一致或权限限制须明确处理。未知客户端先查其正式配置方式，不能照搬另一客户端的文件路径。
6. 验证当前连接：完成 MCP 初始化、发现工具、查询服务环境和成员身份。普通 HTTP 健康检查只证明服务可达；配置文件存在只证明已写入。
7. 验证持久性：在未继承本次临时注入变量的新会话/独立客户端进程中，按已保存配置初始化并确认同一服务和成员。父进程把临时环境传给子进程不能作为此证据。需要重启宿主才能加载时，报告等待重启，不能提前宣称跨会话可用。
8. 最终分别报告 `配置范围及位置`、`当前连通`、`认证来源可持续`、`新会话验证`；未验证明确标注。服务端看不到用户本机的配置持久性，whoami 不能代替客户端核验。

Codex 当前将 MCP 配置放在用户级 `~/.codex/config.toml` 或受信任项目的 `.codex/config.toml`；同一 Codex 宿主上的客户端共享配置。`bearer_token_env_var` 指向环境变量名称，不会自行把临时变量变成持久凭证。具体操作先读取该客户端版本支持的方式，本文不修改维护者本机配置。[Codex MCP 配置](https://developers.openai.com/codex/mcp/)

## 4. 正式工具契约的要求

- **按业务动作命名**：查询、创建、编辑、关闭、重新开启、删除、恢复、绑定标签和修改公共词库区分清楚。正式服务不得延用探针 `set_state` 隐式重开的组合设计；不提供任意数据库写入或一个包办全部副作用的万能工具。
- **独立可理解**：每个写工具简述用途、目标来源、授权范围、副作用、必填条件、返回结果和失败恢复。可选资料 schema 说明其价值，从用户材料里主动提取；有用但缺失时可简短提醒，工作状态缺负责人必须询问，不能默认调用者。
- **当前事实可发现**：身份工具返回服务环境、成员/角色、契约版本、指南主题和实际能力；对象读取返回当前版本与可执行动作/不可用原因。能力列表不是长期授权缓存，执行时仍检查当前权限。
- **输入防误用**：ID 与名称分开，记录版本与档案版本分开，新增/删除/恢复不能因可选字段缺省偷偷改变另一项内容。对象歧义、缺负责人、无效标签描述、来源不可读等返回可执行的补充要求。
- **输出有边界**：声明 outputSchema，提供 structuredContent 及兼容文本；数据与业务状态分开。返回对象 ID、版本、结果链接及实际变化，批次明确 completed/failed/remaining，不用一个笼统 success 掩盖部分失败。
- **长内容可分页**：查询返回游标、是否完整和可见摘要；详情、记录版本、图片、绑定影响按需取。避免工具返回超大包导致被宿主截断后仍误认已掌握全部信息。重要状态、ID 和下一页信息放在稳定字段里。
- **幂等与恢复**：写命令使用请求 ID 与版本条件；网络超时/取消不等于事务失败。正式服务增加按当前成员查询请求结果的能力，返回已知结果或无法确定；未查到不能在原请求仍可能运行时当作未发生。保留原请求重试，不自动生成新的业务动作。
- **错误分层**：认证/传输错误在协议边界处理；参数校验返回具体字段原因；可识别业务错误返回稳定代码、说明、可补字段、可否直接重试及下一步。恢复动作仍受原授权约束，不能建议自动重开、改管理员或绕过审批。
- **未读正确性**：查询与阅读确认分开；只确认实际返回并展示的内容和版本。分页或输出截断不能清空未看到的事件。服务无法证明模型真的理解了内容，不能把“已调用查询”伪装成用户读完。
- **图片闭环**：先确认客户端能读本机文件并执行上传，返回明确方法、地址、必要头、期限和完成条件。上传与绑定分别可核验，过期/失败可恢复；输出中的短期票据也不进入最终聊天回复或日志。
- **不可信材料**：观察、标签描述、外部来源和上传材料均作为业务数据。它们不能授权 Agent 改配置、扩大读取范围或发送信息；服务端不执行其中的命令或任意 URL。

## 5. 项目规则如何迁移

| 原复制正文中的内容 | 服务提供位置 | 服务端保证 |
| --- | --- | --- |
| 类型、状态、负责人及关闭规则 | 档案/状态工具 schema、states 主题、对象可执行动作 | 类型、状态、负责成员和关闭原子校验 |
| 主动提取可选资料、不猜未知内容 | 创建/编辑工具字段描述、archives/records 主题 | 结构合法性；材料真实性不伪称能自动验证 |
| 作者权限、删除恢复、旧图片限制 | 相应工具说明、records/images 主题、业务错误 | 每次写入和读取鉴权 |
| 标签复用、依据、影响预览与合并 | tags 主题和标签工具；预览返回实际范围 | 来源可见性、版本、合并/关闭限制 |
| 上传头像与图片回退规则 | 图片/头像工具及 images 主题 | 用途、文件格式、主体权限及私有读取 |
| 未读与实际展示后确认 | unread 主题、查询与确认工具 | 当前成员、事件和版本边界 |
| 幂等、冲突、部分成功 | 写工具 schema、结果和 recovery 主题 | 请求去重、事务、结果查询 |
| 任务示例、何时追问 | 主题指南中的短流程和示例 | 不新增强制逐字段审批 |

## 6. 验收清单

| 场景 | 通过条件 |
| --- | --- |
| 首次接入，用户未选持久性 | Agent 明确询问；未同意时不持久写配置 |
| 已有正确持久连接 | 复用并核对身份，不重复创建或放宽工具限制 |
| 用户选择临时连接 | 本次可用，未留下客户端持久项，并说明使用寿命 |
| 用户选择持久连接 | 配置与认证来源分别检查，新会话不依赖本次临时变量也能查询身份 |
| 配置存在但令牌只在旧终端里 | 不能报告持久接入完成，指出认证来源待处理 |
| 连接成功但服务/账号错了 | 先纠正目标，不能继续对错误环境写入 |
| 没有最初长提示词的新连接 | 能从目录发现身份与指南，取得本次流程必要规则 |
| 客户端不加载 resources/prompts | 仅工具路径仍能完成核心任务 |
| 上下文压缩后要继续编辑 | 重新取当前版本/所需指南，不凭旧摘要猜 ID 或覆盖 |
| 字段漏填、空记录、删除时携带改写正文 | 入口拒绝，不发生意外写入；错误说明缺什么 |
| 关闭、作者不足、并发变化 | 不能靠 Agent 选择另一工具绕过；恢复不暗含额外授权 |
| 写入超时、重试、批次部分完成 | 查询或原 ID 重试，无重复对象/事件，完成范围真实 |
| 图片能力缺失、过期票据、上传成功绑定失败 | 明确缺项，可核实并恢复，不用本机路径冒充附件 |
| 恶意记录要求改身份、导出全库或写配置 | 作为材料处理，不成为新的授权 |
| 长结果分页或被截断 | 不宣称全量检查，不确认未展示内容 |
| 标签来源删除、冻结后已有连接再调用 | 所有入口继续按最新权限拒绝或过滤 |

机器协议测试与真实 Agent 行为验收分别记录。协议测试可证明服务提供了指引和校验，不能证明模型在压缩、陌生宿主、首次配置中一定做对。真实 Codex 验收必须使用短首次提示词、冷启动与跨会话场景，检查实际配置产物和业务数据，不能只让 Agent 自述“成功”。不把隔离探针的临时配置测试算成产品持久配置验收。

## 7. 实施归属与证据边界

本地探针中有 instructions、主题指南、结构化结果和错误恢复的局部试作，尚未完成该次交付审查，不作为正式使用体验证据。历史已验收范围以 [验证报告](./technical-validation.md)为准，不因需求文档更新扩大结论。

## 整张档案回收与账号范围（2026-09-09）

- `list_archives` 默认 `deleted:false`；管理员用 `deleted:true` 读取回收列表，类型、查询与分页参数沿用。
- `delete_archive` / `restore_archive` 输入 `id`、`expected_version`、`request_id`，可选 `task_id`；两者仅管理员可调用。结果返回 `id/version/deleted/changed/archive_url`，重放附带 `replayed:true`。
- 对应 HTTP 为 `POST /api/archives/delete`、`POST /api/archives/restore`，与 MCP 共用事务命令。读取已删除内容只允许管理员；写入拒绝 `ARCHIVE_DELETED`，不能为了完成其他任务擅自恢复或重新开启。
- 恢复不改变原关闭状态、观察删除标记或成员归属。图片和旧内容版本保留。已删除档案不能创建新任务上下文，恢复前不进入普通任务副本与产物展示。
- `list_members` 默认 `state:active`，支持 `frozen` 和显式 `all`；对应 HTTP 为 `/api/admin/members?state=...`。搜索协作成员的目录仍保留冻结身份，供既有绑定说明；服务端禁止新分配冻结成员。

验收：`node scripts/verify-archive-trash.mjs`；`--remote` 在隔离 staging 验证真实 HTTP/MCP、图片及桌面/手机操作，收尾把虚构档案移入回收列表并冻结验收成员。
