# Agent 接入提示词

接入页保留短说明与“复制提示词给 Agent”按钮。首次消息只负责连接、临时/持久选择和核验；业务任务与规则由 MCP 提供，避免依赖第一次聊天里的长手册。

2026-09-09 用户修正接入要求：点击复制时自动创建当前成员的专用 MCP 凭据，复制的正文必须包括真实地址与完整认证配置，使没有浏览器能力的 Agent 也能接入。唯一模板见 [bootstrap-prompt.txt](../app/shared/bootstrap-prompt.txt)。认证配置用通用 `mcpServers` JSON 表达 HTTP 地址和 Authorization 请求头，Agent 按所在客户端转换格式；连接管理网址仅供成员撤销，不是 Agent 的前置认证步骤。

正式站与原型共用 `app/ui/AgentHandoff.tsx`。正式按钮创建 90 天连接，凭据只在当前页面内存保留；重复复制和剪贴板失败后的重试复用同一份凭据，撤销后再次复制则换发。“为另一个 Agent 复制”创建独立连接。剪贴板不可用时显示可选中正文；成功复制后不常态显示认证值，不写入 localStorage/sessionStorage。原型只说明需在正式站操作，不生成假凭据。

模板要求 Agent 先检查已有连接；用户尚未选择时询问是否需要持久配置，已明确选择则继续。选择持久配置后，说明客户端及保存范围，分别检查连接设置、认证来源和新会话可用性。“配置已保存”和“新会话已验证”分别报告。

连接完成后，从 MCP 获取系统用途、当前身份、实际能力与本次任务指南。有现成任务或材料就继续处理；只请求连接时给一个简短的使用入口。服务自带内容可以重新取得，不代表所有 Agent 在压缩上下文后都会自动记得或读取。

产品任务与主动帮助的设计见 [MCP 的 Agent 使用体验](./mcp-agent-experience.md)；业务规则位于 [服务内 Agent 主题指南](./mcp/agent-guide.md)。配置和服务承载细节见 [MCP 对接设计](./mcp-design.md)。旧 S2 验收使用预先准备的认证，不能替代 Issue #25 的“从实际复制正文开始、无浏览器、无预配置 MCP、新会话可用”验收。
