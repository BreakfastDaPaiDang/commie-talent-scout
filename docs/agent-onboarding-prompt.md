# Agent 接入提示词初稿

用途：供产品接入页“一键复制”。页面只显示短使用说明与一个复制按钮，以下技术内容给 Agent 阅读。占位符由正式应用填入服务地址和配置说明；不在本文件保存个人凭证。此稿定义完整操作原则，实际工具名称以连接后的 MCP 工具说明为准。当前原型的精简复制正文见 [protocol.js](../prototypes/frontend/src/protocol.js)，它明确尚无正式连接，不能据此声称已经接入。

## 可复制正文

请帮助我连接并使用“康米巨星猎头系统”。它是早餐社内部的人物与外部组织资料协作系统，用于沉淀基础信息、观察记录和当前接触情况。

MCP 服务地址：{{MCP_SERVER_URL}}

当前客户端配置与认证步骤：{{MCP_SETUP_INSTRUCTIONS}}

先检查你是否已有这个系统的 MCP 连接。若没有，请在当前客户端支持的配置方式下完成接入，必要时引导我在猎头账号的连接管理中完成本人授权。不要在普通聊天中索要明文密码或个人令牌；个人凭证只用于认证，不写入观察记录、公开文件或任务回复。没有有效地址或授权时如实说明，不虚构连接成功。连接后先确认当前成员身份及权限，并读取可用工具的说明。

### 如何理解系统

- 关注对象分为人物和组织，一个对象对应一份档案；对象不是系统登录用户。
- 人物状态有：视奸观察、个人接触、引荐中（待人事组接触）、人事审核、已加入待对接、已入伙、已弃用。
- 组织状态有：视奸观察、个人接触、组织交流、已弃用。
- 状态只描述当前情况，没有先后顺序，不要求逐个经过其他状态。
- 人物引荐中、人事审核、已加入待对接及组织“组织交流”属于工作状态，必须绑定至少一名负责成员，可多人。其他状态可选关联成员。状态与绑定分开，详情仅显示当前状态关联。分配不等于授予管理员权限。
- 人物的已入伙、已弃用，以及组织的已弃用，都会关闭档案。已弃用包括失联或不再关注，不另设已失联状态。
- 关闭后不能修改档案内容，也不能添加、编辑、删除或恢复观察记录。需要继续维护时先重新开启。
- 实体历史线包含成员写的观察记录和系统产生的操作事件；不要为了复述一次状态操作额外创建一条空洞的观察记录。
- 标签库分人物与组织两套，标签以“类别：名称”展示，描述解释通用含义，绑定依据说明它为什么适用于具体档案。标签不代替业务状态或原始观察。

### 如何执行我的任务

1. 根据我的任务查询相关档案。创建前先检索可能的已有对象；同名不代表同一个对象，不能擅自合并或把资料关联给不确定的人。
2. 按我提供的材料和操作意图工作。已明确授权的任务直接执行；只有对象、内容或期望操作存在会影响结果的歧义时，再简短询问。不要根据你对材料的猜测，擅自更换状态、分配负责人、关闭或重新开启档案。
3. 写观察记录时清楚表达事件或材料、资料来源和必要背景。原始信息、我的判断和你的推测应能区分；未知内容保留未知，不补造联系方式、关系或事实。
4. 短情况直接写短记录，长材料按段落整理；不强制长标题或固定篇幅。需要解释停止关注的原因时，可以按我的要求在关闭前补一条观察记录。
5. 图片按服务提供的上传方式提交，取得附件标识后绑定记录。不要把你电脑里的文件路径当成成员能够打开的图片地址；上传失败时如实说明，不能声称图片已提交。
6. 你以当前登录成员的身份操作：普通成员仅可编辑、删除和恢复自己的观察记录，管理员可处理任意记录。账号管理也必须遵守当前成员权限，不能通过其他入口绕过限制。
7. 删除记录是可恢复删除；恢复仍属于原作者的原记录。修改、删除、恢复由系统保留历史，不改写系统操作事件。
8. 对网络中断或结果不明确的写入，先核实操作是否成功再重试，避免重复档案和观察记录。
9. 完成后简短报告实际完成的操作，附档案或记录链接；失败和未完成部分明确列出。查询结果不是自动授权你对这些对象采取进一步动作。

### 如何维护标签

以下规则属于待实现的 v1.5 能力。先检查服务实际提供的工具；当前前端原型尚未实现标签，不虚构可以调用的工具或已经完成的写入。

- 获得整理标签的授权后，先读相关材料和现有绑定，再搜索对应人物/组织词库及描述，优先复用。确无适用项时可在授权范围内创建类别和有简短描述的新标签；不要为词形近似反复新建同义项。
- 从观察材料推导的绑定必须引用实际读取的记录与版本，必要时附简短说明；用户明确给出的材料或绑定指令可作为独立依据并注明种类。没有材料就保留未知，不能把职业、计划、用词或关注议题推定成能力、政治身份、健康诊断或可靠性。
- 新材料没有提到某个旧标签，不代表可以移除。范围明确且材料充分的维护直接完成，存在影响结果的冲突才追问；只查询、总结不等于授权自动更新。
- 修改名称、描述、类别前先获取实际影响预览，查看可见绑定及差异，再按已授权范围携带版本条件提交。词义明显改变时新建并选择迁移，不能通过改描述重解释全部旧档案。
- 合并/停用只可在管理员权限下执行，区分“从档案移除标签”和“修改整个标签库”。已有授权无需再增加逐标签审批；预览不构成操作授权，范围变化时仍需澄清。
- 关闭档案不能修改绑定、依据或重点；历史与关闭快照保留当时词义。来源于已删除观察的绑定沿用来源可见性，不通过标签摘要、筛选、统计或移除来源引用绕过限制。
- 重点标签是共享展示选择，最多 3 个，不按猜测自动设重点。按标签查询采用同类“或”、跨类“且”，报告采用的筛选条件。
- 完成后报告复用了哪些标签、新建或移除了哪些、依据来自哪里；部分失败明确说明，不把计划当成已经执行。

### 任务示例

- “查一下某人的档案，概括最近三条观察记录，附原记录链接。”
- “把下面的文字和两张图片整理成该组织的一条观察记录。”
- “把这份人物档案的状态改为个人接触，将指定的两名成员关联为接触用户。”
- “删除我刚才误发的那条记录。”
- “恢复我昨天删除的记录；如果档案已关闭，先告诉我当前情况。”
- “带我逐条查看未读更新。”
- “根据这三条记录整理这个人的可证实技能标签，优先复用；没有提及的旧标签保留。”
- “找出有视频剪辑能力，并会英语或日语的人物档案。”
- “查看这个标签的定义和绑定范围，说明这次更名会影响什么。”
- “根据已给出的合作资料，整理这个组织的已有能力和可用资源，附依据。”

删除期间仅原始作者和管理员可查看具体正文、历史版本和图片，普通成员不得通过其他入口绕过。阅读对应内容后由接入流程自动确认阅读进度，不让用户额外执行“标为已读”。档案不设置别名或简介；人物和猎头账号支持上传头像，按上传图、QQ、默认形象的顺序回退；组织只用上传图或默认形象。

创建或整理资料时，主动检查已提供材料中的联系方式、QQ、关联成员、来源链接和图片，在授权范围内填写。不要因为字段非必填就忽略。对有用的缺失资料可一句追问或完成后提醒，不逐字段盘问；工作状态缺负责成员时，必须在保存前请用户指定，不能擅自默认调用者。非工作状态可先保存，提醒有需要时补充关联。
