同日用户反馈折叠入口不显眼（Issue #53）：改为常显的新手推荐卡片，标题、简介与下载按钮一直可见，只折叠安装和接入步骤。

DSH 配置文案依据安装包发布当日的[官方桌面文档](https://github.com/deepseek-ai/deepseek-harness/blob/59d2e01575f4114fb323af89a60420628a06638f/apps/desktop/README.zh.md)核对：欢迎窗口提供 API Key 表单，通过“保存并继续”进入工作区。官方页面已核对包含桌面端下载入口；本次未安装 DSH 或执行充值，不将官网页面核对与本站接入链路验证描述为 DSH 完整端到端验收。

2026-09-09 用户修正接入要求：点击复制时自动创建当前成员的专用 MCP 凭据，复制的正文必须包括真实地址与完整认证配置，使没有浏览器能力的 Agent 也能接入。唯一模板见 [bootstrap-prompt.txt](../app/shared/bootstrap-prompt.txt)。认证配置用通用 `mcpServers` JSON 表达 HTTP 地址和 Authorization 请求头，Agent 按所在客户端转换格式；连接管理网址仅供成员撤销，不是 Agent 的前置认证步骤。

正式站与原型共用 `app/ui/AgentHandoff.tsx`。正式按钮创建 90 天连接，凭据只在当前页面内存保留；重复复制和剪贴板失败后的重试复用同一份凭据，撤销后再次复制则换发。“为另一个 Agent 复制”创建独立连接。剪贴板不可用时显示可选中正文；成功复制后不常态显示认证值，不写入 localStorage/sessionStorage。原型只说明需在正式站操作，不生成假凭据。

2026-09-10（Issue #42）用户反馈：已提供地址、凭据与授权，Agent 仍花费六分半巡检配置，最后只询问持久化而没有连接。旧模板“先检查并询问”的前置要求已移除，服务端 connections 指南与初始化说明同步修正。

现在优先使用已有原生 MCP 工具；没有则以现成 HTTP/终端能力初始化并调用 whoami。成功后报告实际账号名称、用户名、角色、环境及几类功能，再主动询问是否保存连接供未来会话使用；已有明确选择不重复询问。工具可见不等于拥有全部操作权限。仅连接时不扫描业务档案、不加载全部指南。默认先完成当前会话，得到保存授权后才实施持久化；同时交代的业务任务不等待持久化答复。真实失败后针对性排查，暂时性网络错误最多重试一次，约 30 秒未完成先反馈阻塞；不绕过客户端权限。

只有执行了持久化才报告保存位置、认证来源及新会话验证。客户端配置管理是另一项操作，例如 [Codex 官方命令文档](https://learn.chatgpt.com/docs/developer-commands#codex-mcp) 中的注册与配置管理；不能把它作为用户已授权的当前 HTTP 身份验证的必经步骤。

连接反馈只依据 whoami 返回的身份和能力，不将功能摘要说成已读取业务档案。有现成任务或材料就按需读取指南并继续处理。服务自带内容可以重新取得，不代表所有 Agent 在压缩上下文后都会自动记得或读取。

2026-10-12：移除“仅连接时到此完成”与后续选择之间的冲突，明确实际工具调用、结果反馈、询问保存的先后顺序。业务草稿审阅放到“后续业务协作”，服务端初始化说明也先提供连接步骤，避免将发布确认误用于身份验证。模板中的认证配置保持原始 JSON，URL 保持纯文本；不嵌入 Markdown 链接或 HTML 空格实体。
