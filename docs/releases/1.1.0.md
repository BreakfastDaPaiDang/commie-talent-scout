# 1.1.0 发布与回退

关联开发任务：#156。基线主分支 `b4c1730782f0de705513ad7b58b4c4306d04ec31`，独立开发分支 `codex/personnel-recognition`。

本版新增观察关联的人员认可、每社员月度两份额度、三人触发审核、撤回及轮次历史；网页与 MCP 共用权限与事务。知识独立库维持原有数据和服务版本，不迁移知识共识。

## 数据与兼容

人事库新增迁移 `0043_personnel_recognition.sql`：轮次、认可及历史身份表，唯一约束和受保护人事状态触发器。旧社员与在途任务保留，不伪造历史票，不清空数据。

现有 MCP 读取与任务交付接口兼容。直接创建已入社档案、直接切换审核/入社阶段、手动创建 `source: rule` 任务不再支持；这属于有意收紧的写入规则。新客户端应使用人员认可和既有自动任务交付。历史社员补录入口不在本版范围。

## 发布

PR 通过类型、架构、生成规则、迁移、主站与知识库测试、DOM、历史原型以及真实 HTTP/MCP 桌面手机验证后合并。沿用 `Checks and production release`：先 D1 备份与迁移，再发布 Worker，检查健康版本和实际发布资源。无需人工复制数据库或修改知识库绑定。

## 回退

已推送标签 `rollback/before-personnel-recognition-20261114`，指向上述基线；完整 Git bundle 保存于本地 `tmp/personnel-recognition-notes/before-recognition.bundle`。

应用故障优先按既有发布流程回滚至该标签对应 Worker 或提交回退 PR，**保留 0043 表、历史记录与数据库约束**，不反向删除迁移或恢复整库覆盖新数据。旧版仍可读取档案和完成在途任务，但新人员认可入口不可用，直接发起审核仍会被数据库约束阻止；因此旧 UI 的直接推进按钮可能显示拒绝。回退后需告知这项限制并尽快前向修复。

若确需恢复数据库，须先另行确定数据恢复点及处理发布后新增数据的方案，不把代码回退等同于删库重建。
