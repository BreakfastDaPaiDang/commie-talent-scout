# 1.0.0.1 工作倾向推送：已收束规则

这是 1.0.0.1 的实现边界，不改写 1.0.0 原 PRD 的任务、身份和权限要求。

## 任务创建

创建时自动带入档案、任务类型、标题、目的模板、交付要求模板和默认期限。用户只确认或修改目的和交付要求；不填写负责人、协作者、复杂进度或审批轮次。档案页是主要入口，任务看板保留“发起临时工作”兜底入口。

人事审核、入社对接和月度任务按既定业务规则自动生成；有明确类型的手动工作也可以参与倾向匹配。没有明确类型的临时工作仍进全组看板，但不进入倾向推送。任务创建不改变档案身份或业务状态。

## 倾向与匹配

成员在账号设置中自己编辑“愿意接手”的任务类型，支持具体类型和“全能”。倾向表示愿意收到提醒，不代表能力认证；不新增资格系统。没有倾向的成员仍可从全组看板主动领取。

匹配只选择未冻结、具有人事系统账号且当前有权限查看任务的成员。任务类型为自定义临时工作时不匹配。匹配结果按成员名称和稳定 ID 排序，推送后再检查权限。

## 推送和领取

任务创建时推送一次；第三天仍待接手时再推送一次；第七天进入管理员待处理列表。不自动选择负责人。被推送者必须主动领取，领取成功后只有一名当前负责人；其他推荐停止，已发通知历史保留。

推送只显示任务类型、标题、关联对象、目的摘要、期限和查看/领取入口，不能泄露受限观察或来源。已读不等于领取，不改变责任。

## 管理员介入

管理员待处理列表显示无人匹配或有人匹配但无人领取、推送对象、推送次数、最近时间和当前期限。管理员可以继续推送、修改任务、直接指派、取消或暂时保留。直接指派立即建立负责人，要求简短理由并留历史；不会伪装成主动领取。被指派者可以使用现有“放弃任务”回到待接手，重新匹配并保留原指派历史。

成员改变倾向只影响后续匹配；仍开启、待接手且有权限的任务可以重新匹配。已领取、关闭或取消的任务不重新推送。管理员指派后停止后续普通推送并收回其他人的待领取推荐。

推送只使用站内消息和铃铛，不发送站外通知。看板范围分为全组任务、推荐给我、我负责、管理员待处理。
