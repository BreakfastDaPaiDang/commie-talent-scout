# 图片阅读与传输

Issue #49、#50（2026-09-20）：长截图缩进查看窗口后难以阅读；观察图和头像重复加载缓慢。

共享 `app/ui/ImageViewer.tsx` 对长宽比大于 2 的图片默认按宽度显示，其他图片默认适应窗口。缩放范围 5%–800%，支持原始尺寸、鼠标拖动、Ctrl+滚轮、键盘 +/-/0 与双指缩放；围绕操作位置缩放，保留原图清晰度。正式站和原型均使用该组件。

## 测量与修正

正式站一次前测中，3 张观察图约 128–240 KB，头像约 14–120 KB，首字节约 1.3–2.7 秒。图片均为 `private, no-store`，重新打开仍完整下载，单次请求总耗时约 2–32 秒。原始测量保存在本地 `tmp/verification/image-performance-before.json`，这是该次网络样本，不能推断所有成员的速度。

- 图片、上传头像、QQ 头像返回 `private, no-cache`、ETag 与 `Vary: Cookie, Authorization`。浏览器可保存字节，但每次复用必须向服务端重新核验；正常未变内容返回无正文的 304，不读取 R2 图片正文。
- 路由先验证账号与凭据，业务层再验证档案删除状态、观察删除权限、私有上传归属与历史头像引用，最后判断 ETag。撤销凭据及权限变化仍立即拒绝；错误响应为 `no-store`。
- 图片读取将权限条件合并为一次精简查询，不再加载完整档案、观察摘要、成员及历史状态绑定。头像所属对象检查也不加载完整档案。
- QQ 头像已有缓存过期时，先返回可用缓存，在 Worker `waitUntil` 内续取。原有刷新租约、24 小时缓存与失败退避继续有效；首次无缓存时仍需要等待上游。

未启用公共图片地址或额外收费图片服务，没有重编码历史原图。此次主要减少重复传输和服务端工作，首次加载仍受成员至 Cloudflare 的网络及原图体积影响。

## 验证

`tests/image-delivery.test.mjs` 覆盖 304 不取 R2 正文、精简查询、私有上传、已发布/删除观察、删除档案和 HTTP 凭据撤销；`tests/avatar-cache.test.mjs` 验证 QQ 续取不阻塞缓存响应。远程真实接口用 `verify-image-delivery.mjs --remote`，完整图片交互用 `verify-images-state-ui.mjs --remote`。桌面/手机长图、拖动和双指缩放检查纳入 `check-ui.mjs`，继续保留历史原型对照。
