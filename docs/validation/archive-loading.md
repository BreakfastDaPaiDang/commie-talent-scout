# 组织档案加载标题 · Issue #19

打开组织卡片时，组织详情接口尚未返回，标题与无障碍名称错误地先显示为人物；响应后才变成组织。地址 `/organizations` 和“组织”导航一直保持，因此是加载标题闪现，不是路由重定向。

`ArchiveDetail` 现在接收入口已知的 `type`。资料未返回时沿用该类型，资料返回后使用服务端类型，不把缺失数据默认为人物。布局和路由不变。

回归：在 DOM 测试中暂停详情请求，修复前得到“人物档案”，修复后等待期间与完成后均为“组织档案”。`verify-archive-loading.mjs` 在实际构建的桌面／手机页面点击组织卡片，暂停接口并分别记录等待期间与完成后的地址、导航、标题和无障碍名称。

验证：类型检查、4 个 DOM 测试、构建通过；桌面与手机组织加载回归通过；历史原型未变化布局四宽度对照、25 项完整编辑和发布区验证、本地真实接口界面 6 组检查通过。
