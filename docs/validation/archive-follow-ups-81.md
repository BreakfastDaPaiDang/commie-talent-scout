# 超期外部档案跟进任务 · #81

日期：2026-10-12。用户授权自动生成并补齐当前三个超期对象；生产发布与补生成结果记录在 #81。

## 机制

- 每小时 scheduled 入口运行，复用 archiveOrderCte 和 archiveReminder 的 30/7 天判定；排除社员、关闭、删除档案。
- 规则模块只返回 SQL 事务计划；定时入口按档案原子提交，管理员 HTTP/MCP 补生成通过 command() 提交相同计划。
- 标签“接触跟进”、P2、7 天截止，初始待领取；发起人早纪（人事版）。不新增前端布局或操作，沿用关联任务、任务簿和大厅。
- 新增 nullable automation_rule/automation_key 和唯一索引，以档案 ID、规则和触发更新时间去重；同类开启任务同时抑制新的周期。事务内再次检查版本、更新时间、开启/未删除条件。
- 创建不修改档案，取消后不重复生成同一轮；更新后再次超期才允许新一轮。档案关闭也不自动交付跟进任务，仍由负责人提交。
- 一次最多 40 项，后续小时继续处理剩余对象；管理员可限定最多 50 个档案 ID。现阶段不新增通用周期配置 UI。
- 定时执行不依赖成员 MCP 凭据。兼容旧表 created_by 的非空外键，保存一个既存管理员 ID；业务发起人为 system、initiator_id 为空，创建事件 actor_id 为空且 source=system，不记录或声称该管理员发起/授权。未来主体模型升级时可移除此存储兼容项。
