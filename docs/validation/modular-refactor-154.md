## 如何退回

本轮没有数据库迁移，回退代码即可保留期间新增的业务数据；不要把数据库恢复到旧快照来回退这次重构。

1. 从当前 `origin/main` 建立回退分支。
2. 在 #154 的发布记录取得本轮 PR 的合并提交，对它执行 `git revert -m 1 <合并提交>`，保留后续历史；不要对 `main` 强制重置。
3. 提交回退 PR，运行主站与知识服务检查，再由现有发布流程更新两个服务。
4. 核对两套流水线、主站与知识服务健康检查，并抽查任务交付和知识库读取。

需要离线取回旧代码时可使用上述标签或 Git bundle。发布流程原有的部署前备份、健康检查失败自动回退仍然有效。原工作区的未提交文件可按 `manifest.json` 逐项找回；不要整目录覆盖之后的新工作。
