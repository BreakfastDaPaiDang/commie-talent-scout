# v0.1.0 S10 正式部署、流水线与恢复验收

2026-09-09，对应 Issue #14。正式应用已部署至 `https://scout.dapaidang.org`，版本为 0.1.0；首版里程碑和 GitHub Release 尚未宣布完成。具体结果见 [JSON](./v0.1.0-s10.json)，操作说明见 [运维文档](../operations.md)。

## 已完成

- 生产 D1、图片 R2 与 staging 隔离；备份库和恢复演练库均私有。运营管理员已按维护者要求建立并验证登录，最低密码长度调整为 10 位。引导管理账号仍使用单独的临时密码并要求首次更换；明文仅保存在本机排除提交的私有文件中。
- 37 项服务测试、5 项组件交互测试、类型检查、构建、4 宽度历史原型对照、25 项展开界面检查、18 项卡片检查、11 项注意力与标签检查通过。[GitHub 原生检查任务](https://github.com/BreakfastDaPaiDang/commie-talent-scout/actions/runs/34281722887/job/102247811596)也全部通过。
- `release.mjs` 已在 staging 和 production 实际执行私有备份、迁移、Worker 部署、首页/资源/鉴权/D1 冒烟与私有成功记录写入。首次正式部署遇到本机 DNS 负缓存，未误报成功；确认公共 DNS 与域名绑定正常、清除本机缓存后重新完成全流程。
- 隔离恢复 staging 快照：33 张表逐表规范化哈希相等，31 个图片对象逐个 SHA-256 相等。包括账号、观察版本、删除状态、附件、词库、依据、合并历史和关闭快照。恢复目标未挂载公开 Worker。
- 恢复后实际运行 30/180 天请求清理；分别验证读取时拒绝过期正文、事务失败完整回滚、重复清理保持业务数据、匿名累计不重复。
- staging 实际部署一个新 Worker 版本后故意使后续检查失败，自动恢复原代码并通过冒烟；档案、观察、版本、附件引用数量不变，没有执行数据恢复。另有 6 项发布逻辑测试覆盖备份/迁移失败停止、回滚失败、首次部署无旧版本及迁移校验。
- 正式域名实际浏览器与 MCP SDK 共 7 组：强制改密与管理权限、登录/列表/草稿/PNG 发布/手机原图、手机编辑与历史、作者/管理员删除和图片可见性/恢复、标签依据和任务审阅、关闭只读、冻结立即失效。脚本关闭浏览器代理。仅 2 个虚构档案、2 个测试成员，收尾关闭/冻结并作废管理员旧会话。
- 正式验证中有一次网络连接超时；随后完成收尾并重跑相关路径。另一次等待误选手机隐藏列表中的“已弃用”，修正选择范围并补验剩余关闭/冻结步骤。报告明确记录续验，不将失败轮次删除后称为首次全部通过。
- 静态首页原先不经过 Worker 安全头中间件，现用 `public/_headers` 补齐并通过云端实际响应检查。用量脚本实际运行成功，CPU 限制 2,000 ms，日志采样和查询参数脱敏已配置；每日备份/用量任务已提交。

## 调用拒绝分类修复

真实检查发现 SSE 响应先返回时，业务回调会在等待响应正文期间完成。旧逻辑随后用通用 `INVALID_TOOL_REQUEST` 覆盖 `ARCHIVE_CLOSED` 等已确定拒绝码。现于正文读取后重新核对回调结果，只对没有业务结果的协议错误应用通用分类。

`verify-mcp-error-journal.mjs` 在修复前复现失败，修复后分别验证关闭拒绝保留业务码、缺少参数仍保留协议分类。已有 6 项日志脱敏与任务审阅测试继续通过。
