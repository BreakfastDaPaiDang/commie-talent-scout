# 首次设置正式密码的流程优化

2026-09-09 · Issue #27。

用户报告设置正式密码后登录失败。定向检查发现提供的新密码与实际保存结果一致，正式登录接口也成功；未取得发生问题时浏览器提交的内容，因此没有认定为服务端存错密码，也未重置用户账号。

原网页保存新密码后退出当前会话并回到登录页，需要再次输入。现在使用刚提交的新密码建立新会话并直接进入工作台，减少与浏览器保存的旧临时密码混淆的机会。其他旧登录和 MCP 连接仍按原机制失效。若改密成功、自动登录失败，明确提示密码已经保存，回到保留账号名、清空密码的登录表单。

`node scripts/verify-password-setup.mjs --remote` 使用独立虚构成员验证。旧版在“设置后直接出现工作台”检查失败；新版构建通过 `CTS_UI_BASE` 接入真实 staging API，3 项检查通过：自动进入工作台、旧临时密码拒绝、模拟自动登录失败后的正确提示和表单状态。账号在收尾冻结。类型检查与构建通过；部署沿用 GitHub 必要检查。

这项变更消除了首次改密后的重复登录步骤；不将它描述为已复现并修复“正确新密码被服务端拒绝”。用户实际故障浏览器的提交内容仍不可见。
