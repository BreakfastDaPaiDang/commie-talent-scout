# v0.1.0 S7 删除与恢复验收

2026-09-09，对应 Issue #9。实际浏览器、HTTP/MCP、搜索/未读和真实 Codex 删除恢复验收均已通过。正式站已上线，其作者/管理员删除、图片可见性与恢复亦已完成浏览器和 SDK 检查，见 [S10](./v0.1.0-s10.md)。

删除/恢复通过同一业务层用于 Web 与 MCP。原作者及管理员可操作开启档案，管理员删除不改变原作者恢复权限。操作校验当前凭证、权限、档案开启状态、记录版本与删除状态，并与事件、活动时间、请求收据同批提交。删除/恢复只推进记录状态版本，不增加内容版本，不删除正文、历史或图片引用。无变化不制造事件，重复请求返回原收据。

网页提供删除/恢复确认、“已删除”筛选、删除人及时间、历史和原图；错误后可重读当前状态继续。已关闭档案可查看有权内容，但无删除/恢复操作。已删除视图仅返回原作者/管理员有权记录。

`scripts/verify-observation-state.mjs` 使用真实 HTTP 与 MCP，四组检查包括：管理员编辑和删除后作者身份/创建时间/旧图保持；默认列表与已删除列表权限；详情、历史、旧图片地址、派生标签、摘要、动态与关闭快照隐藏；作者恢复、状态与编辑竞争、相同请求竞争重放、不同恢复竞争冲突；关闭对所有角色的锁与显式重开后恢复。

此前非交互客户端因 `approval policy is never` 阻止删除；该失败保留在 JSON 中。现由真实 Codex app-server 接收并转交确认请求，用户明确批准后，仅响应当次调用。只读沙箱与工具 destructiveHint 保持。

2026-09-09T07:29:58Z，三组真实客户端验收通过：核对身份和目标后删除；独立冷启动恢复相同记录、原作者及唯一内容历史；再次冷启动读取已关闭档案并拒绝删除，没有隐式重开。删除刚提交时客户端因等待人工确认耗尽总时限，未保存最终回复；续验先核对原调用的成功收据及状态版本 2，再直接进入恢复，未重复删除。恢复后状态版本 3、内容版本 1，原作者不变。测试凭证已撤销并清除复制的认证信息。
