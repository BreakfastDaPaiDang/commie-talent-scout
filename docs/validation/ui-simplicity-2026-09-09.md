# 前端七项反馈整改

对应 Issue #16。用户截图暴露了上次验收范围不足：基础布局投影一致，不能证明展开后的表单与发布体验一致。

## 完成的调整

- 常态档案只留一个“编辑档案”维护入口，状态、成员、联系方式为资料展示；内部集中资料、状态与成员、标签、头像。关闭档案保留明确的重新开启入口。
- 状态使用可直接选择的单选项；联系方式与链接改为紧凑行、备注按需展开。资料/状态页签切换保留输入，手机保存按钮固定可见。字段源代码与样式已移入 app/ui，原型引用相同组件。
- 观察发布只呈现正文、图片、必要草稿状态与发布操作，隐藏原生文件控件。删除新建和编辑中的手动时间输入。提交时间来自服务端，页面明确使用 Asia/Shanghai；编辑保留既有发生时间资料。
- 全部/我负责/有未读显示服务端分页前聚合的档案数。计数遵循搜索和筛选；个人未读口径使用既有可见性与阅读条件。
- 标签采用无底色、无边框的文字排布，保留类别、名称、重点及查看依据能力。动态的操作明细按需展开，去掉重复的历史位置解释与来源技术标签。
- 数字、日期和正文统一使用本地 Noto Sans SC，预加载字体；验证实际中文与数字字形，不只检查 CSS 字符串。
- Agent 页改为“让 Agent 帮你干活”，说明查档案、整理材料、写观察，移除排错与保留期限说明。

## 证据

`node scripts/verify-ui-simplicity.mjs` 最初精确复现六项失败。当前 25 项检查通过，覆盖四种宽度、完整展开界面、手机保存按钮、服务总数不同于当前页条数、标签、实际字形和洛杉矶浏览器中的东八区显示。

真实接口回归发现“关闭编辑窗后迟到的标签刷新会重开窗口”。通过刻意扣留刷新响应的浏览器测试复现；修复为只更新仍打开、同一档案、版本不倒退的编辑窗。回归通过。

历史原型 531ab51 与当前界面的基础几何投影在 1920、1440、1024、390 四宽度通过。此项不宣称完整像素或体验相同。本次用户要求的字体、发布区和表单变更独立验收，历史源代码保持在不可变 Git 提交中。当前原型实际资料保存、链接重开保留和共用状态选项也通过交互验证。

18 项服务/纯函数测试、3 项 React DOM 测试、类型检查、正式及原型构建通过。150 档案、1200 观察、600 万正文字符的五页检索共 11 次读取；新增计数仅发生在第一页。

本地真实 HTTP/MCP/浏览器六组通过：联系方式/备注/资料链接、标签绑定与总数、观察编辑和历史、真实 PNG 上传发布及图片显示、状态与负责成员、筛选及头像入口。测试只使用合成档案，收尾关闭档案并撤销临时凭证。
