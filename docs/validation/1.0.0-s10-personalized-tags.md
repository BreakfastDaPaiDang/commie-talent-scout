# S10 / Issue #64：个性化标签本地验收

日期：2026-09-29。需求：[Issue #64](https://github.com/BreakfastDaPaiDang/commie-talent-scout/issues/64)、[PRD 1.0.0 §5、§10](../PRD-1.0.0.md)。基线提交 `6a8c6ba`，实现位于功能分支 `feat/64-personalized-tags`。本文记录本地结果，不表示正式站已发布或 1.0.0 已完成。

## 审查与改动

现有 `Tags.create` / `Tags.batch` 没有多人使用门槛，普通成员已经能够创建类别、词条和单档案绑定。网页与 MCP 共用这些命令；`TagState`、`TagMaintenance`、`TagMigration` 已处理来源权限、定义版本、关闭快照、合并及恢复。因此不修改表结构、权限或绑定算法，不增加私人词库、评分、自动画像或后台采集。

- 网页创建表单从“新建通用词条／通用描述”改为“新建标签／词义说明”，输入提示明确单对象适用；定义维护表单同步措辞，布局与操作保持。
- MCP 标签指南和创建工具说明明确：优先选用含义合适的词条，多人复用不是门槛；公共定义解释词义，对象的来源、范围及判断原因放入绑定依据。
- 服务初始化、`whoami`、整理和观察主题沿用的 `compressionRule` 明确个性化特征与非接触观察。观察指南及创建工具区分材料来源、授权账号提交身份和实际沟通者。
- 原有“未提及不等于移除”、来源版本读取、受限内容保护及用户确认范围保持。
- 成员指南、标签专题和 MCP 文档同步；旧版 PRD 和历史验收不改写。

专用脚本的可复现演示：

1. 创建普通成员和新 MCP 连接，从服务取得新版标签、观察指引；不注入业务指引副本。
2. 新建虚构“雨声地图作者”档案，记录来自公开作品集、未实际沟通的观察。事件保留 `source=mcp`、提交账号 ID，正文明确来源，不将提交人当作沟通者。
3. 普通成员在真实网页创建“雨声地图偏好”标签并绑定。该词条只有一个绑定；桌面和 390px 手机完整创建表单可操作，无横向溢出。
4. 网页补充引用观察的依据；MCP 读取实际观察版本，再修订依据范围。检查旧/新依据均在历史中、确认时间存在。另发一条未提旧标签的观察，原绑定和依据保持。
5. 网页刷新可见最新依据，能打开所引用版本。MCP 澄清定义后，网页定义历史仍显示原词义，维护表单显示新定义。

运行产物保存在被忽略的 `tmp/verification/`：`personalized-tags-local.json`、桌面/手机创建与依据截图、定义历史/维护截图，以及既有脚本报告。已查看本轮手机创建、手机依据和桌面详情截图。脚本结束撤销连接、冻结测试成员，并将其虚构词库和档案可恢复删除。首次脚本运行遇到 Playwright 对嵌套 label/textarea 的精确定位问题，改用表单内明确控件定位后通过；没有因此修改产品行为。

## S06 联合验收与限制

本项继续使用现有 `type=person` 词库，无数据库迁移或类型拆分，可兼容 0.1.1。社员与外部人物必须共享同一人物词库；个性化不意味着私人可见，权限仍由原档案与来源规则决定。

S06 / [#60](https://github.com/BreakfastDaPaiDang/commie-talent-scout/issues/60) 的身份切换已实现。联合验收复用单对象标签，核对外部人物转为社员时原档案 ID、标签 ID、人物类别 ID、绑定依据、确认时间、定义历史及旧链接保持，网页和 MCP 查询一致。更完整的外部人物 → 社员 → 外部社友和受限来源云端验证由 S11 汇总。

## S10 / S06 联合验收补充（2026-10-08）

`node scripts/verify-person-tags-compat.mjs` 本地通过 2 组检查。脚本创建虚构 `type=person` 类别和标签，通过 MCP 绑定依据，将同一人物档案从外部接触切换到“已入伙”，核对不变的档案 ID、标签 ID、绑定依据、社员范围及手机详情。结束时删除虚构档案并清理本次创建的词库。

本轮使用真实 MCP 协议客户端与浏览器，不等同于独立外部模型的自由执行验收。#64 已关闭，#54、#65、#66 仍开放；软件版本保持 0.1.1，未完成 1.0.0 的正式迁移与上线验收。
