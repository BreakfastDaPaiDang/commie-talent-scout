# 标签系统产品规则

版本：v1，2026-09-08。属于 [PRD v1.5](./PRD.md) 首版范围；用户已确认引入标签、人物/组织分库、类别可创建、描述必填、优先复用、修改影响可见，以及标签定义与绑定依据分离。本文中具体权限、数量、排序、合并流程均为可调整的开发默认值，无需逐项等待批准。词条见 [初始标签库](./tag-catalog.md)。

当前交付为产品与实施文档，前端原型、正式服务及 MCP 均尚未实现标签。既有技术验证不覆盖本功能。

## 1. 标签、类别与绑定

- 人物、组织各有一套标签库。类别与标签分开维护，稳定标识独立于名称；同名不表示跨库相同含义，禁止跨类型绑定或合并。
- 合法展示为“类别：名称”，例如“技能：视频剪辑”。快捷输入可接受一个英文冒号并规范为中文冒号；类别名和标签名本身不含冒号、换行或控制字符。去除两端空白，类别名 1–24 字、标签名 1–40 字，描述去空白后 1–160 字；不允许只填类别或名称。
- 同库类别名唯一，同类别标签名唯一。比较时规范全半角和拉丁字母大小写，保留用户选择的展示形式；不自动把不同词义视为同义词。
- 标签必须有简短通用描述；名称、所属类别与描述可以维护。类别本身可创建、更名、选择预设颜色；类别描述可选。类别不是互斥分组，同一档案可以绑定多个同类标签。
- 标签绑定属于档案，保存添加者、添加时间、最后确认者/时间及可选依据。同一档案对同一标签最多有一条当前有效绑定；重复添加返回既有结果，不覆盖旧依据或产生重复事件。
- 标签不替代业务状态、负责人、观察正文或任务适配判断；不把每个类别都做成必填项。

## 2. 依据与信息质量

标签描述解释词义，绑定依据解释具体适用原因。手工选择已有标签可以直接保存，无依据时显示“手工添加，未附依据”；后续可以补充，不弹出逐字段盘问。

Agent 基于观察材料整理时必须关联它实际读取的观察记录及版本，可附简短说明；也可依据用户明确提供的材料或绑定指令保存独立说明及来源种类。不能虚构记录链接、自动诊断、把身份推定成能力，或为了凑齐分类添加标签。来源种类区分观察材料、本人明确自述、成员明确指令与无附加依据的手工绑定；它们不是可信度评分。

“本人明确自述”或“成员明确指令”若来自已有观察记录，仍须保留记录引用并沿用来源权限；不能只改来源标记就把它变成独立材料。

依据尽量包含范围：会剪辑哪类视频、什么语言对、什么时间可投入、哪些设备能使用。阶段性特征不自动过期；有新材料时可以调整，材料未提及旧标签不表示应该移除。Agent 发现冲突先检查旧依据，有会改变结果的歧义再询问。第一版不提供置信度分数、性格评分或自动录用/排除。

## 3. 权限与生命周期

| 操作 | 普通成员 | 管理员 |
| --- | --- | --- |
| 检索标签库、查看定义及有权查看的绑定情况 | 可以 | 可以 |
| 创建类别和标签，澄清描述、更名或调整类别 | 可以，保留版本与影响预览 | 可以，同样留史 |
| 在开启档案增减标签、维护依据、选择重点 | 可以 | 可以 |
| 合并重复标签、停用/恢复标签或类别 | 不可以 | 可以，先查看影响预览 |
| 修改关闭档案的绑定、依据或重点 | 不可以，先重新开启 | 不可以，先重新开启 |
| 永久删除已使用的类别、标签或绑定历史 | 首版不提供 | 首版不提供 |

上述动作均使用当前成员身份；冻结、撤销与 MCP 权限遵守主 PRD。普通成员有权维护共享绑定，但不能通过修改绑定去编辑他人的观察正文。更名、澄清与合并的历史均可追溯。

关闭时保存该档案标签的当时定义、类别名称、依据及重点展示状态。公共词库后续更名或澄清只更新开启档案的当前展示，不改写关闭快照和历史。重新开启时重新采用当前词库定义，并在开启结果中列出定义差异；停用或已合并标签保留旧绑定并标出状态，不自动迁移或删除。类别颜色是当前界面辅助，不作为历史事实快照。

## 4. 修改、合并与影响预览

标签详情能查看定义、版本、可见当前绑定数量与分页档案列表，区分开启/关闭；可逐项查看有权读取的依据。类别更名或停用预览覆盖其下标签及绑定。计数按当前有效绑定计算，移除历史另查；本人成员权限下不可见的绑定不进入计数、列表或示例。

更名、改描述或换类别前，网页和 MCP 返回同一份影响预览：前后值、当前版本、可见绑定数量、影响的开启档案、保持快照的关闭档案，以及合并/停用时的处理方式。执行需带上该次预览的版本条件；定义或绑定集合已变化时重新预览，不能只依赖用户之前看到的数字。

预览是可审阅的操作结果，不是额外的人类审批流程。已有明确授权时，Agent 可以先读取预览再执行；只有扩大授权范围、改变词义的意图不清等情况才询问。工具返回影响预览不代表自动授权修改。

- **更名或释义澄清**：保持同一特征含义，创建定义新版本，开启档案采用最新定义；历史与关闭快照保持原文。系统提供差异，语义是否相同仍由操作者负责判断。
- **含义明显改变**：例如把“视频剪辑”扩大成“视频全流程制作”，新建标签，再选择有依据的开启档案迁移；不以改描述方式批量重解释旧绑定。
- **合并**：只在同库重复词义之间进行，指定保留标签和要迁移的开启档案。目标已绑定时合并来源依据、避免重复，不丢原添加者或历史；重点位置冲突保留目标现有位置。关闭绑定不迁移，预览清楚列出保留项。源标签停用并保留跳转关系，不能把绑定历史改写成从未有过源标签。
- **停用**：禁止新增绑定，保留现有绑定、历史与查询能力；可由管理员恢复。停用类别同样禁止其下标签新增绑定，不级联删除。

## 5. 依据删除后的可见性

标签不能成为绕过观察记录删除权限的副本。来源于观察材料的依据保留记录/版本引用，其说明不作为全员可读的脱离来源摘要保存。

读取时按当前成员重新检查来源权限。若一个绑定仅由调用者无权查看的观察材料支撑，该绑定的标签、依据、重点位置及绑定事件内容均不向其展示；标签筛选命中、聚合数量、列表摘要、未读和 MCP 同样遵守。原作者与管理员仍按原权限查看。若存在独立且可见的依据，标签可以展示，但受限来源及其说明仍隐藏；历史中的旧依据也执行相同检查。

有来源的绑定不能被系统自动降级成“无依据手工标签”来规避限制。成员后来有独立材料时可以明确补充，记录来源及操作历史。公共标签描述不承载任何具体档案的私有材料。恢复观察记录后，根据当时权限恢复可见性，不重新添加绑定、不制造重复动态。

## 6. 电脑端交互与检索

- 列表姓名/状态区域之后、观察摘要之前显示最多 3 个重点标签；没有指定重点时按类别及名称稳定展示前 3 个可见标签，余项显示“+N”。重点由成员在档案内共享维护，不是每人的私人偏好；Agent 不按猜测自动调整重点。
- 详情按类别展示全部可见标签，点击可查看描述、具体依据和确认时间；“添加标签”先搜索当前库，找不到时可直接新建并绑定，不跳进复杂管理表单。
- 标签库是独立维护入口，人物/组织可切换；支持按类别、名称、描述检索，展示绑定数。空库、无命中、停用标签、权限不足和并发冲突有明确反馈。
- 同类同色，类别名始终可见，不能只靠颜色区分；采用少量低饱和度预设色，不改变红色主操作和未读标识，保持已审阅的大字号。
- 标签筛选与状态、负责人、关键词组合使用。首版同类多个标签为“或”，跨类为“且”；例如“英语或日语”且“视频剪辑”。界面和 MCP 明示此语义，不扩展任意布尔表达式编辑器。
- 绑定增减、依据变更和重点变更生成档案历史，更新活动时间并进入其他成员未读；一次整理多个标签合并为一条有明细的事件。重复无变化保存不产生新活动。
- 公共词库的更名、释义和颜色维护只生成词库历史，不批量顶起所有相关档案或产生大量未读。明确迁移绑定仍属于对应档案的新动态。关闭快照不受词库维护影响。

## 7. MCP 业务契约

以下为待实现的动作职责，不是现有可调用工具名；正式 schema 与网页共用校验、权限和事务。

| 动作 | 必须提供的结果或约束 |
| --- | --- |
| 查询类别与标签 | 指定人物/组织库；返回名称、描述、版本、停用状态和调用者可见绑定数；支持分页检索。 |
| 查看标签及绑定 | 返回定义历史、分页绑定、开启/关闭状态及可见依据；不能只返回标签名称。 |
| 创建类别/标签 | 新建前优先检索；重名返回可复用的既有标识，不静默覆盖定义；标签描述必填。 |
| 预览/提交词库修改 | 区分更名澄清、换类别、合并、停用/恢复；返回具体影响，并提交版本条件；合并与停用受管理员权限约束。 |
| 添加/维护/移除绑定 | 分清创建词条与绑定词条；指定档案和标签 ID，遵守来源权限、关闭锁定、幂等及档案版本；推导绑定附可追溯依据。 |
| 设置重点标签 | 最多 3 个当前有效绑定；不绕过来源权限，不把“重点”变成人员得分。 |
| 按标签查询档案 | 返回符合约定“同类或、跨类且”规则的可见结果，不能凭隐藏绑定使档案命中。 |

典型已授权任务：“根据这几条记录整理可证实的技能标签，优先复用词库；材料没有涉及的旧标签保留。”Agent 先查询档案、材料和词库，再执行范围明确的更新，报告复用/新建/移除和仍有歧义的部分。只要求查询或总结不构成自动维护标签的授权。

## 8. 验收与首版边界

| 场景 | 验收结果 |
| --- | --- |
| 空描述、缺分隔项、同库同类重名、跨类型绑定 | 拒绝非法输入或返回可复用对象，不产生半成品绑定。 |
| 两名成员并发创建同一词条或修改定义 | 不生成重复词条；过期修改返回冲突和刷新依据。 |
| 先查到绑定数，另一人随后增减绑定 | 原影响预览失效；执行前重新获取范围。 |
| 重复添加/移除或重复提交同一请求 | 不重复生成绑定和动态，保留首次结果；不存在的绑定移除为无变化。 |
| 公共词条改名时同时存在开启/关闭档案 | 开启档案采用当前定义；关闭快照和旧历史保留旧定义；词库维护不制造批量未读。 |
| 已合并标签仍被关闭档案引用 | 旧绑定及定义仍可读，不自动迁移；重开后提示其状态。 |
| 删除唯一来源、具有独立来源、随后恢复 | 分别验证隐藏派生绑定、仅保留独立可见依据、恢复可见且无重复动态。覆盖筛选、计数、事件、未读、MCP。 |
| 普通成员合并或修改关闭绑定，冻结成员调用工具 | 服务端拒绝；网页隐藏入口不是权限边界。 |
| 开启档案批量整理标签、修改重点后跨页返回 | 展示稳定，历史明确，可回溯；一次整理只生成一条汇总事件。 |
| 真实 Codex 查库、复用/新建、绑定、预览更名并查询 | 与网页结果、权限、版本和错误一致；记录实际验证证据。 |

首版包含：类别/标签库、描述、绑定与依据、重点展示、筛选、定义和绑定历史、影响预览、管理员合并/停用、网页/MCP 一致操作。暂不做：自动后台打标、向量检索、评分排行、自动决策、类别互斥引擎、自动过期、自由布尔查询、整库批量改写和独立审批系统。
