# 外部 Agent 请求留存与需求分析

2026-09-08 · v0.1.0 待实现方案。目的：观察成员实际让 Agent 做什么、怎样完成、卡在哪里，再决定 MCP 产品优化方向。不是接管外部 Agent，也不要求成员填写使用反馈表。

## 1. 能看到什么

服务能够记录到达 MCP 的请求和自身执行结果。标准工具调用携带工具名与参数，不自动附带用户原始提问、完整聊天或模型内部过程；这些内容只有客户端或 Agent 明确传入才可获得。[MCP 工具调用规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

因此区分三种事实：自动采集的调用记录、Agent 提交的任务说明、业务服务实际完成的变更。不能把任务摘要当用户原话，也不能把自报完成当作服务确认。初始化中客户端可以报告名称和版本，它不是可靠的模型身份或认证依据。[MCP 生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)

## 2. 首版存什么

| 数据 | 内容与用途 |
| --- | --- |
| 单次请求 | 服务端调用标识、时间、已认证成员、凭证的非秘密标识、工具/契约版本、客户端自报名称与版本（取得时）、耗时及结果状态 |
| 请求内容 | 经字段筛选的业务参数，包括实际提交的观察正文、标签操作及依据；大内容采用受权限控制的引用，并标记截断/未留存，不能假装保存完整 |
| 执行结果 | 成功、无变化、拒绝、失败、结果不明；错误分类、产物 ID/版本、观察与标签的实际变更、未完成范围，不重复保存整份查询响应 |
| 任务上下文 | Agent 提交的一句话任务目的、原始用户请求片段（如实际提供）、材料类型、任务关联 ID；标明原话或 Agent 摘要，允许未知 |
| 关联关系 | 一次整理所含的查询、观察、标签调用及产物；业务幂等请求 ID 与每次调用尝试分开，重试不重复计算任务或成果 |

请求内容是私有业务数据，不是输出到普通运维日志的原始 HTTP 包。认证头、Cookie、密码、个人令牌、上传签名/票据均不留存；账号类工具采用字段白名单，正文中识别到的凭证也应去除，不能只过滤顶层字段名。

用户原始聊天可能只被 Agent 看过，服务收到的只有压缩后的观察。此时只能分析“提交内容与后续变化”，不能声称能检查遗漏了哪些原始信息。需要原料与结果对照时，可在本次材料整理入口接收该任务相关的源材料或引用，明确其用途；不要求上传外部 Agent 的无关会话。

## 3. 关联任务，但不为了统计增加使用负担

优先把任务说明作为现有整理入口的轻量上下文，一次提供后返回服务生成的任务关联 ID，后续调用复用；具体入口形态随正式工具设计确定。不强制每次调用复述用户意图，不要求人为补一整套“开始任务/结束任务”操作才能办理业务。

缺少上下文或关联 ID 时仍记录调用，任务归属为未知。不能把同一成员、同一凭证或相近时间的调用直接认定成一个任务；多个 Agent 可能共用同一成员身份。事后推测的聚类必须标为推测，与明确关联分开。

任务有实际产物不等于用户满意；无结束报告不等于失败，没有后续修改也不等于被认可。Agent 报告、服务结果、人工评价分别保存。任务关联 ID 仅用于分析关联，不是权限凭证，也不要求采用协议中的异步 Tasks 能力。

## 4. 数据如何决定优化

- **按任务看需求**：材料整理、纯查询、状态维护等，分类从真实样本归纳，可调整；保留任务原文/摘要，避免预设分类遮蔽新需求。缺任务上下文的请求另列，并报告覆盖率。
- **按步骤看摩擦**：一次整理查了多少次、在哪一步失败、是否重复提交、是否产生多余调用。查询可能为压缩服务，不能单凭查询调用多认定查询是主要需求。
- **按结果看压缩**：观察与标签是否共同更新、复用和新建如何分布、移除是否有依据。数量只能描述行为，不能给压缩质量打分。
- **按样本看返工**：关联后续编辑、删除、撤销或恢复，抽样看原因；后来的事实变化与整理错误区分，不把所有修改都算失败。

首版先支持按时间、工具、结果及任务筛选和查看关联产物，用少量汇总与人工审阅即可，不先建设复杂分析看板或自动评分。样本受实际活跃成员与可见数据范围影响，报告应说明时间范围、任务关联覆盖率与样本数。

## 5. 存放、访问与保留

请求数据放在私有应用存储，普通运行日志仍只留诊断元数据。首版管理员可审阅请求；业务产物和来源引用仍按当前权限读取，不通过分析入口向普通成员开放全库。后续若开放成员查看本人任务，也须重新检查引用资料的当前权限。

请求正文与派生内容不应成为绕过观察删除权限的副本。维护来源关联，详情读取与导出均执行来源规则；未关联的原始材料先保持管理员私有，不混入共享搜索、标签描述或聚合内容。

可逆初始默认值：详细请求参数、任务文本及源材料副本保存 30 天，调用元数据保存 180 天，之后只保留不含正文和个人标识的汇总；到期清理覆盖关联正文/源材料副本，正常业务观察与历史按原规则保留。该期限用于控制成本和避免重复积存材料，可据实际分析需求调整。

接入说明简短告知会留存调用及提交内容用于排错和改进，无需每次调用弹窗。分析记录写入失败不应让已经成功的业务被误报失败，需监控记录缺失并在统计中披露覆盖情况；必要业务审计仍遵守其原有事务要求。
