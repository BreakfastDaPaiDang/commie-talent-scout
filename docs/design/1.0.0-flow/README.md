# 1.0.0 业务流工作台原型

2026-09-29。对应 #56 的入社接续方案，需求以 [PRD](../../PRD-1.0.0.md) 第 4、6、7、9、15 节为准。本记录解释界面选择，不另立业务规则或完成清单。

## 打开与体验

在仓库根目录执行 `npm run dev --prefix prototypes/frontend`，打开 <http://127.0.0.1:5181/?flow=1>。全部为虚构内存数据，刷新或“重置演示”复位；顶部可切换身份、推进演示日期。

1. 初始打开林澈的审核任务，点击“领取审核”→“完成审核”。可选填写留档结果；完成后仍是外部人物。
2. 点击“确认入社”，查看身份变化和后续任务说明，再确认。立即转到社员页，同一档案保持展开，原观察和标签保留。
3. 新对接任务显示“待接手”。点击“领取对接”才成为负责人；完成审核的人不会自动承担对接。
4. 也可放弃任务，切换沈舟再领取；延期、评论、完成与重开在“过程与历史”中保留。完成任务可以不新增观察。
5. 外部人物中的江禾可发起引荐；组织展示长期大使及独立任务负责人。陆遥有独立月份的任务与过去失败记录。推进日期可观察负责人提醒、到期无人领取或未完成的结果。

## 界面选择

任务看板分为待领取、正在进行、已结束，卡片直接呈现对象、责任和期限；提供全组、我负责、待领取与任务类型筛选。右侧详情持续展示对象及下一步，避免完成动作后失去上下文。详情将当前工作、档案观察、过程与历史分开，底部保留主要操作。手机采用全屏详情，完整表单与保存动作可达。

入社进度条用于解释当前情况，不是强制按序审批。明确入社可以独立执行；审核完成不推定身份变化，新增观察也不推定任务完成。需要人接手的阶段始终显示无人负责或具体负责人。交接采用 PRD 已有的“放弃后由下一人主动领取”，没有强制指派。

视觉使用暖白背景、细边框、清晰文字层级和克制红色；保留现有品牌、共享图标、顶栏、页签、弹窗。新界面位于 `app/ui/`，正式化时在同一组件上接入真实数据。

## 演示边界与后续接入

原型从固定虚构日期开始，新任务与领取默认加七天，日期表单采用东八区 18:00，提醒窗口为一天。这些仅用于演示，不确认生产任务期限参数。

当前覆盖入社接续与主要任务动作，不代表 #56 全部范围已完成。任务手动创建与内容编辑、评论修改/恢复、完整周期/结果筛选、退出与资料变化联动、真实月度生成仍需继续实现。标签页只读预览，统计沿用旧原型；完整资料维护、材料、阅读回执与 Agent 接入继续在原入口演示。

本原型没有新流程的数据库、真实鉴权或 MCP 接口；内存模型不得直接当作服务端授权依据。#55 集中规则、#57—#62 持久化任务及自动化、#65 综合验收仍按各 Issue 推进。正式接入须保证身份变更与对接创建的一致性、并发领取唯一性，以及失败重试不会重复创建任务。
