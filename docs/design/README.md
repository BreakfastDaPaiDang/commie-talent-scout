# 首版设计说明

日期：2026-09-08。以用户最新确认替代早期暖纸、书卷气及口号方案。

## 已确认的方向

- 现代化左翼、扁平化，加入构成主义语言；当前以红、黑、白探索。
- 首版简洁，每一部分都应经过设计。图形、字号和留白服务于结构和层级。
- 暂不加口号。待骨架形成后单独设计整活方式，不预先限定为文案。
- 为后续扩展保留余地，但不在首版摆放没有实际用途的入口、模块或装饰占位。
- 当前采用“灵感探索 → 方案整合 → 前端原型”的流程：在已确定的风格内，通过多张静态生图探索具体艺术设计和排版，由开发者筛选、提炼统一设计，再实现可操作的前端原型。此项按用户最新建议替代之前不做原型的安排。
- 准确功能、状态、权限和响应式行为由设计与实现负责，不要求生图准确呈现全部功能。
- 头像不是重要信息；默认去掉人物列表和作者旁的大头像、黑色姓氏方块。无头像时也应是完整成品。

## 各区域的设计约束

| 区域 | 首版要求 | 后续扩展方式 |
| --- | --- | --- |
| 品牌与导航 | 标识紧凑，人物、组织、未读入口清楚；品牌不挤占工作区域 | 标识与导航分离，可替换图形、按需增加入口 |
| 列表与筛选 | 名称、状态、负责人、观察摘要形成层级；搜索和筛选紧凑 | 附加筛选折叠展开；可选头像不改变行结构 |
| 档案详情 | 基础资料与观察内容分区，详情有足够阅读宽度 | 次要资料按组展开，避免不断加宽页头 |
| 记录与编辑 | 人写的观察最醒目，系统事件轻量；编辑、图片与历史操作清楚 | 记录正文、附件、操作区各有稳定位置 |
| 管理与接入 | 与业务页面共用字体、间距和控件；复杂说明按任务分段 | 后续增加能力沿用页面结构，不做独立风格 |
| 空白、加载、错误及窄屏 | 认真设计，功能反馈简明；无头像、无图片也完整 | 整活表现可局部加入，不承担必要操作提示 |

构成主义通过比例、排版、几何图形关系体现，不依赖上传附件恰好是一张红黑海报。强对比集中于少数重点；正文、作者、时间、系统事件拉开视觉重量。界面字体以无衬线为主。具体尺寸和组件在实现时确定，不要求逐像素复刻生图。

## QQ 头像：后续增强建议

用户提出人物与成员可关联 QQ 号并周期更新头像。当前记录为可选增强，不据此新增 QQ 登录、身份验证或自动人物归并。

- 人物 QQ 沿用联系方式结构；多条 QQ 不任意猜选来源，实施时允许指定其中一条。成员的 QQ 是独立的可选资料，人物与成员不因为 QQ 相同自动关联。
- QQ 号以字符串保存。头像只作辅助辨识，姓名仍是主要信息；无 QQ 或无可用头像时直接使用无头像布局。
- 实施默认建议：设置或变更来源时拉取一次；采用 24 小时新鲜期的缓存，过期后在访问时刷新，无需为低优先级头像单设定时任务。网页读取系统缓存，失败保留旧图，首次失败回退到无头像。若后续需要即使无人访问也定时更新，再增加后台刷新。
- 头像来源变更后清除旧来源的展示关联，避免新 QQ 仍展示旧 QQ 的头像。清空 QQ 后停止同步。
- 缓存刷新属于展示维护，不触发档案活动排序、历史线或未读通知。成员主动修改 QQ 等业务资料仍遵循相应资料变更规则。
- 已关闭人物档案暂停头像刷新，重新开启后可继续，维持关闭后不修改档案图片内容的现有规则。冻结成员停止刷新其账号头像。
- 拉取与缓存独立于业务页面，未来替换来源不影响记录结构。不提前开发多平台头像框架。

2026-09-08 已读取用户提供的 `mmm8091/makeshift-dev` 实现，参考提交 `5724b917d200b2e1ae6051a52267ba5565dd9d03`：其[头像路由](https://github.com/mmm8091/makeshift-dev/blob/5724b917d200b2e1ae6051a52267ba5565dd9d03/app/api/avatar/qq/%5Bqq%5D/route.ts)校验 5–12 位数字 QQ 号，请求 `https://q1.qlogo.cn/g?b=qq&nk={qq}&s=100`，返回 24 小时新鲜期及 7 天 stale-while-revalidate 的公开缓存头，上游异常时返回默认 SVG；[QQAvatar 组件](https://github.com/mmm8091/makeshift-dev/blob/5724b917d200b2e1ae6051a52267ba5565dd9d03/components/qq-avatar.tsx)统一使用本域代理并懒加载。

本项目沿用同域代理和缓存的思路，并保持内部访问边界：按实体/成员标识鉴权读取头像，不复制公开匿名路由和长期公开浏览器缓存设置；缓存落在服务端私有存储。实际头像刷新需要实现缓存元数据和过期检查，不能仅假定复制 Next.js 的 `cache: force-cache` 即具有相同的 Workers 行为。用户提供的示例已足以作为实现参考；本次是源码审阅，不声称完成本系统云端头像集成测试。

## 已实现的原型

[运行说明](../../prototypes/frontend/README.md)。本机服务：桌面 `http://127.0.0.1:5181/`，窄屏 `?preview=mobile`，登录 `?page=login`。

- 桌面使用导航、档案列表、详情三列；详情可展开阅读，正文宽度受限。窄屏转为列表/详情单页与抽屉导航。
- 品牌收缩为小型几何标识与系统名称。没有口号、默认头像或姓氏黑方块。
- 记录正文、作者、日期和轻量系统事件分层；输入框默认收起，聚焦后展开。时间线保留全部事件，不截成固定两条。
- 联系方式按需增加；负责人按适用状态维护。业务状态没有流程箭头或步骤顺序。
- 登录、未读、账号、Agent 接入、空白和历史弹窗共用颜色、控件与间距。登录艺术区保留更大的几何关系，业务页只在必要位置用红色。

## 浏览器自查与修订

2026-09-08 在实际 Chrome 中查看桌面 1920 × 912 和 390 × 844 iframe 窄屏预览，并通过真实 UI 操作检查：

- 记录发布、编辑、旧版本、删除、已删除视图和恢复；关闭后编辑区消失，显式重新开启后恢复。
- 新建组织、动态添加邮箱、保存后详情展示、按名称搜索。
- 内置虚构附件的大图弹窗、历史版本中的图片及打开入口。
- 最后一名管理员尝试降权被阻止；账号与 Agent 页面完整布局。
- 演示登录进入工作台，窄屏详情阅读和返回列表。

修订包括：去除偏暖灰背景、加大正文与辅助文字、约束阅读宽度、缩小常驻输入框、扩宽登录表单、增加联系方式、修复全空白名称、重复账号、资料/记录无变化保存、完整时间线，以及窄屏长状态和隐藏导航焦点。

这些是原型 UI 检查，不替代生产测试。浏览器扩展的本机文件上传权限未开启，自动化文件选择器未完成；因此图片 UI 使用内置虚构 SVG 附件验证，不能把它当成 PNG/JPEG/WebP 上传的生产验收。真实 Codex 云端上传的独立证据在技术报告中，两者分开表述。

## 原型的有意边界

虚构数据只存在于内存，刷新复位；未读演示按档案汇总，正式方案要求按事件标记。记录编辑当前只演示文字修改，生产中还需附件增删与版本引用。账号页不生成真实密码，Agent 页不生成真实凭证，QQ 头像未接入。当前没有服务端加载与网络错误，不伪造为已验收状态。后续按技术方案和任务切片落实。
