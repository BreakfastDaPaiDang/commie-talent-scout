# 生产资源库 · 首版需求

依据维护者 2026-11-12 对集中边界问题的答复。资源权威与糖果授权边界继续有效；知识库界面、分类与共识流程以 2026-11-13 的 [知识库工作台](knowledge-workspace.md) 为准。此前提供的两份人事材料仅为参考，以当前交涉为准。

## 已确认目标

采用独立 Cloudflare D1、Worker 与发布流程，复用主站账号身份。首版主要用于发布各组岗位需求和资源入口，并由具体负责人点对点接收人员。新库是资源的唯一权威来源，主站仅引用，不保留可独立维护的第二份资源目录。培养实训及其验收暂缓。

正式成员发布和维护。发布目录对全部正式成员及获得糖果访问授权的人可见；糖果接收者只读，不因获得入口而取得主站人事档案权限。组织成员身份、实际生产参与关系与记录维护授权分别表达。

## 业务范围

- 工作组与项目：登记名称、说明及维护者，可以关联岗位和资源。
- 岗位需求：发布实际工作、能力与投入要求、支持条件、对接负责人；人数可选，未知条件明确待协商。
- 资源入口：登记提供方、获取条件、联系入口、可用情况、类型、用途、说明及必要附件；不实施库存、财务支付和外部账号开通。
- 点对点接收：由正式成员围绕资源指定具体接收负责人，登记接收对象和必要的接收说明，生成可撤销的糖果访问入口，由接收负责人明确确认接收或记录取消。此处收束 Q7，不建立报名竞争、自动占用名额或招聘状态机，不自动改变人事身份。
- 修订与纠错：在本服务内提交类似 Git issue 的问题或修改建议，保留提出者、内容、讨论、依据、关联记录、处理人及结果；采纳修改时形成新版本。与 GitHub 上的软件研发任务严格分开，业务内容不发布到公共 GitHub。
- 参考材料：保留旧文章及历史，不把三人认可、一周期限、旧人事阶段、旧资源审批规则作为新业务规则。

## 交互与权限

网页和 MCP 共用业务规则。主站导航提供生产资源库入口，采用 app/ui 共享界面；糖果接收者通过专属入口查看发布目录及其本人接收安排，不能看到其他人的接收明细。正式成员可以发布记录和提交 issue；记录维护者处理修改建议。接收负责人承担接收确认，发放人可以撤销自己发放的入口。系统管理员的技术维护身份不代替他人作出业务承诺。

AI 可主动检索、比较和起草；发布、采纳修改、发放入口及确认接收按用户明确授权执行，同一明确指令不重复确认。业务数据按任务和权限读取，不把未采纳建议当作当前规则。

正文、外链及必要文档和图片可保存，视频先使用外链。文件随所属记录控制访问。既有材料只保留或整理明确内容，不猜测当前有效性、负责人或岗位条件。

## 数据归属与迁移

既有人物档案、观察和人事任务留在主站。已有资源完整迁入新库并保留原 ID、版本、历史及引用；切换需校验数量与内容，迁移期间阻止并发旧源写入。切换后主站资源接口、MCP 与统计引用均从新库取权威数据；旧表仅作为历史引用兼容材料，不能继续作为独立编辑来源。

账号身份核验仍依赖主站，主站认证不可用会影响正式成员访问。糖果访问凭据独立、可撤销，仅授予本库阅读范围。

## 首版验收

- 正式成员在桌面与手机发布岗位或资源，其他正式成员可检索查看；未授权访问被拒绝。
- 资源信息从独立数据库读取，主站旧入口和 MCP 不再产生第二份权威资源。
- 正式成员提交 issue，维护者采纳后生成新版本；历史、拒绝理由及并发修改冲突可追溯。
- 指定负责人发放糖果入口，接收者可阅读目录与本人安排，不能访问其他接收明细或主站档案；撤销后失去权限。
- 接收负责人可确认接收；不触发人事身份、审核、岗位人数或实训结果变化。
- 附件访问遵循记录权限；桌面、手机完整发布与 issue 表单、真实接口及历史原型回归通过。
- 迁移备份、引用完整性、独立发布和云端实际结果得到验证。

首版完成不代表完整生产宪法、实训系统或人员审核制度已经建立。关联研发任务保持开启，最终业务交付按仓库规则另行确认。
